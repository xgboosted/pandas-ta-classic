# Changelog

All notable changes to this project will be documented in this file.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Changed
* **BREAKING — `df.ta.strategy()` runs serially by default and no longer loses chained columns**: `df.ta.cores` defaulted to `cpu_count()`, so every call started that many spawn processes. Each one commits about 750 MB for OpenBLAS thread buffers, so `strategy("all")` on a million rows with 32 cores drove system commit to 87%; past 90% Windows throttles its WMI arbitrator and `import pandas` blocks indefinitely in a child. The pool also cost more than it saved below roughly 100,000 rows: measured on 32 logical cores, `strategy("all")` took 2.99 s at the old default against 0.19 s serially on 1,000 rows, and 3.04 s against 0.41 s on 10,000, because a spawn pool alone needs 0.5–1.7 s to start. `df.ta.cores` now defaults to `0`. Multiprocessing is opt-in per frame (`df.ta.cores = 8`) or per call (`strategy(cores=8)`, `strategy(executor=pool)`), and `None` resets `cores` to 0 rather than `cpu_count()`.

  The same rewrite fixes a silent correctness bug. Results were handed to a `Pool` in chunks, and a worker saw an earlier indicator's column only when both landed in the same chunk: `[{"kind": "sma", "length": 10}, {"kind": "ema", "close": "SMA_10"}]` produced both columns at `cores=0` and only `SMA_10` at `cores=2`, with no error, because the "column not found" warning was logged inside the worker and the `None` result was then discarded. Prepending one more indicator moved the chunk boundary and lost the chained columns at `cores=4` and `cores=8` too. `strategy()` now resolves its entries into a plan and splits that into ordered stages — an entry reading a column the frame does not have yet starts a new stage — so every mode gives the same columns, in the same order, with the same values, whether it runs serially or on workers. `tests/test_strategy_execution.py` asserts that for `"all"`, a category and a chained custom Strategy with and without a leading indicator; `test_custom_a` now also checks the chained `EMA_5_CLR` it silently lost.
* **BREAKING — `strategy(cores=...)` is read instead of ignored, and invalid values raise**: only `df.ta.cores` was ever consulted, so `df.ta.strategy("all", cores=0)` still started `cpu_count()` processes. The keyword now selects the worker count for that call and goes through `_pos_int`, so `-1`, `1.5`, `True` and `"2"` raise `ValueError: strategy() cores must be an integer >= 0, got ...` instead of being silently replaced. It is also capped at `cpu_count()`, like the `df.ta.cores` setter: one knob reached through two doors had two limits, so `df.ta.cores = 10000` gave 32 on a 32-core machine while `strategy(cores=10000)` would have opened 10,000 processes.
* **BREAKING — running on workers no longer changes how `strategy()` fails.** Four ways the parallel path diverged from the serial one. (1) A worker's exception was wrapped, so `except ValueError` around `df.ta.strategy(...)` stopped working as soon as the caller passed `cores=` or `executor=`; the original is re-raised, and both paths now give `ValueError: sma() length must be an integer > 0, got 0`. The traceback still does not survive pickling, so on Python 3.11+ a PEP 678 note names the indicator; below that the message carries it, which holds for 220 of the 221 indicators that raise for an invalid argument (the exception, `cdl_pattern`, names the pattern instead), but not for an error raised from numpy or pandas internals. (2) A dead worker surfaced as `BrokenProcessPool: ... terminated abruptly`, because the unguarded-`__main__` guard raises in the *child*, whose stderr is gone in a notebook; it is caught and re-raised naming that guard and an externally killed worker (out of memory, segfault), without claiming which. (3) That guard was armed only when `strategy()` opened the pool, so an unguarded script passing its own `executor=` recursed with no hint, and its `finally` disarmed concurrent calls in the same process; it is shared by both paths and refcounted. (4) The "returned no result" warning pointed at `core.py`, one frame short of the caller's line.
* **BREAKING — `df.ta.strategy()` raises on an argument it cannot use**: an unknown string logged `Not an available strategy.` through the package `NullHandler`, added no columns and returned `None`, so the documented `df.ta.strategy("CommonStrategy")` had never worked — a `Strategy`'s name was never matched, only `"all"` and category names were. It now raises `ValueError` listing the categories and pointing at `df.ta.strategy(ta.CommonStrategy)`, and a non-string, non-`Strategy` argument raises `TypeError`. `README.md`, `docs/quickstart.md` and `docs/tutorials.md` are corrected.
* **`strategy()` inside a worker process runs serially instead of failing**: nesting it in a `multiprocessing.Pool` raised `AssertionError: daemonic processes are not allowed to have children`. It now ignores `cores`/`executor` there. Starting workers from an unguarded script, which spawn re-imports, raises a `RuntimeError` naming `if __name__ == "__main__":` instead of forking until the machine stalls.
* **BREAKING — four more `strategy()` arguments that did nothing now raise**, found by auditing the Strategy system the way the worker path was audited. (1) `col_names` with fewer names than the indicator has columns logged through the `NullHandler` and returned, so `{"kind": "bbands", "length": 20, "col_names": ("BBL",)}` added *no* column instead of three; it raises `ValueError` naming both counts. (2) `exclude` was never type-checked, and a string extended the exclusion list character by character, so `strategy("momentum", exclude="rsi")` excluded `'r'`, `'s'` and `'i'` — nothing; a non-list, or a list holding a non-string, raises `TypeError`. (3) `exclude` was popped and dropped for a custom Strategy, where it silently had no effect; it raises `ValueError` pointing at the Strategy's own `ta` list. (4) A `Strategy` entry was only checked when it ran, and then by whatever failed first — `KeyError: 'kind'` for a missing kind, `TypeError: 'str' object is not a mapping` for a plain string — neither naming the entry. `Strategy(...)` now checks each entry's shape where it was written, and an unknown indicator name raises `ValueError: Strategy 'S' entry 1: 'not_an_indicator' is not an indicator` instead of a bare `AttributeError`. Existence is still checked at run time, because custom indicators may be loaded after the `Strategy` is built.
* **`strategy()` reports indicators that added no column**: a missing input column made the run quietly produce fewer columns than entries. It now emits a `UserWarning` naming the indicator and the column it could not find. `beta` and `correl` are left out of `"all"` and category runs unless a `benchmark=` is passed, so `df.ta.strategy("all", benchmark=other)` still computes them, and `ma` unless a `name=` is passed, since without one it would publish a second `EMA_10` beside the run's own `ema`.
* **BREAKING — input shorter than an indicator's window returns an all-NaN result instead of `None`** (issue #145, case B): `ta.sma(close, length=50)` on 10 rows returned `None`, so `df.ta.sma(length=50, append=True)` silently added no column and a strategy on a short frame produced fewer columns than on a long one. Indicators now behave like `close.rolling(50).mean()`: the result has the input's index, the usual name and columns (`SMA_50`; `MACD_12_26_9`, `MACDh_12_26_9`, `MACDs_12_26_9`) and only NaN values. This covers all 149 indicators that returned `None` on a 3-row frame; `vp` keeps its bin rows. Code that checks `if result is None` for short data should check `result.isna().all()` instead. Still `None`: a missing required input (`beta` without `benchmark`), `vp`/`tos_stdevall` with `lookahead=False`, and the deprecated `ichimoku(as_dataframe=False)` tuple, which stays `(None, None)`. Two calls that returned `None` for an invalid argument now raise `ValueError`: `tos_stdevall` with a non-positive entry in `stds`, and `squeeze_pro` when `kc_scalar_wide > kc_scalar_normal > kc_scalar_narrow` does not hold. Results on inputs long enough for the window are unchanged (all 496 output columns hash identically, with and without numba). `tests/test_short_input_contract.py` asserts the new contract for every indicator.
* **pre-commit runs the type check too** (raised in the #142 review): a `mypy-typecheck` hook runs `make typecheck`, the same two passes as CI's `code-quality` job, on push; `default_install_hook_types` makes `pre-commit install` set up both the commit and push hooks, and `default_stages` keeps black, ruff and the stub regeneration on commit. `adosc`, `amat`, `aobv`, `massi` and `tsi` now comment why they drop a strategy-wide `length` (rule 3 in `AGENTS.md`), and the last three use `kwargs.pop("length", None)` instead of a membership test.
* **BREAKING — invalid parameters raise `ValueError` instead of silently using the default**: argument guards across the package replaced bad input with defaults. Numeric: about 290 guards like `length = int(length) if length and length > 0 else 10` turned 0, negative, NaN, bool and fractional values into the default (`ta.sma(close, length=0)` returned `SMA_10`, `length=2.7` became 2); `scalar = float(scalar) if scalar else 100` turned `scalar=0` into 100; `get_drift` turned 0/negative/fractional drifts into 1 and `get_offset` turned non-integers into 0; `macdext`/`mavp` MA-type codes outside 0–8 became defaults. Flags and options: about 76 `bool(x) if isinstance(x, bool) else default` guards turned `talib=1` into False and `asint=0` into True; about 35 string options (`mamode`, `cpr` `method`/`timeframe`/`levels`, `decay` `mode`, `vwap` `anchor`) fell back on non-strings or unknown values, and `ma("emaa")` returned an EMA. All now go through `_pos_int` / `_pos_float` / `_number` / `_bool_param` / `_str_param` / `get_drift` / `get_offset`, which return the default only for `None` and otherwise raise, e.g. `ValueError: sma() length must be an integer > 0, got 0`. Bounds are unchanged (`ebsw` still needs `length > 38`); `stdev`, `rvi`, `hma` and `cdl_z` state their own `length > 1`. Now honoured instead of replaced: `scalar=0`, `ddof=0` (`cdl_z`, `tos_stdevall`) and negative `offset`. Bugs fixed by the same sweep: `slope(as_angle=False)` returned angles, and `decay(mode="exponential")` ran the linear decay. A `df.ta.strategy(..., length=10)` run raises if a selected indicator rejects the value; pass `exclude=[...]`. Results for valid values and defaults are unchanged (all 498 output columns hash identically).
* **BREAKING — `ichimoku()` returns a single DataFrame by default**: the tuple deprecation from 0.8.32 announced this switch for the next breaking release. `as_dataframe` now defaults to `True`; `ta.ichimoku(h, l, c)` returns the visible-period DataFrame (add `append_span=True` for the projected span rows) instead of a `(visible, span)` tuple. `as_dataframe=False` still returns the tuple, now with a `DeprecationWarning`, and is removed in the following breaking release. Code that unpacks `visible, span = ta.ichimoku(...)` must pass `as_dataframe=False` or switch to the DataFrame. `df.ta.ichimoku()` is unchanged.
* **BREAKING — non-Series input now raises `TypeError`** (issue #145): a list, numpy array, DataFrame or scalar passed where an indicator expects a Series used to make `verify_series()` return `None`, which silently dropped the column or surfaced as an unrelated error frames later. 0.8.32 kept returning `None` and emitted a `FutureWarning`. The warning is now a `TypeError` naming the indicator and the type it received, e.g. `sma() expected a pandas Series but got ndarray`. Pass the Series itself (`df['close']`, not `df['close'].values`). `None` for an omitted optional argument is unchanged; a Series shorter than the indicator's window now yields an all-NaN result (see above).

Library code has three inline `# noqa` with reasons and no per-file ignores. `tools/gen_core_stub.py` no longer writes a placeholder stub when one signature fails, so a broken indicator now fails the stub check. ### Deprecated
* **`df.ta.strategy(chunksize=...)` and `df.ta.strategy(ordered=...)`**: both only steered the `Pool` that ordered stages replace. `chunksize` set the batch size whose boundaries decided whether a chained entry saw its input, and `ordered=False` switched to `imap_unordered`; results are now always in the order the entries are listed. Passing either emits a `DeprecationWarning` and has no effect; they are removed in the next breaking release. They need an explicit check rather than simply disappearing, because `strategy()` forwards unknown keywords to the indicators — that is how `strategy(length=10)` works — so a retired keyword would otherwise pass through in silence.
* **`max_drawdown(all=...)` and `df.ta(version=...)`**: renamed to `all_methods` and `show_version` (the old names shadowed the builtin `all` and the module's `version` import). The old names still work and emit a `DeprecationWarning`; they are removed in the next breaking release.
* **`tsignals(trend_reset=...)` and `xsignals(trend_reset=...)`**: documented as "value used to identify if a trend has ended" but never read, so it has never changed a result. Passing it now emits a `DeprecationWarning`; the parameter is removed in the next breaking release. Its default is now `None` (was `0`).

### Added
* **`df.ta.strategy(executor=...)`**: pass any `concurrent.futures.Executor` and `strategy()` runs on it instead of opening a pool of its own, so worker start-up — about 0.66 s each, most of it loading the numba cache — is paid once rather than per call. Within a stage the tasks are split round robin into one group per worker and only the columns that stage can reach are sent, so the DataFrame is pickled once per group rather than once per indicator. Roughly 3x faster than serial at 100,000 rows and at a million, and slower below about 100,000, where starting workers costs more than the indicators do. `docs/strategies.rst` covers when this pays, the `if __name__ == "__main__":` guard that spawn requires, and why `OPENBLAS_NUM_THREADS=1` must be set before numpy is imported rather than in the pool's `initializer=`.

### Removed
* **BREAKING — `cpr(interval=...)`**: accepted but never read; previous-period levels come from calendar days, weeks and months, so the bar interval does not matter. It is removed without a deprecation step (AGENTS.md rule 11 exempts parameters that never had an effect), and passing it raises `TypeError` instead of being swallowed by `**kwargs`. Callers that passed later `cpr` arguments positionally must shift them by one; a shifted value now fails validation instead of being misread.
* **`slope(vertical=...)`**: accepted since the upstream code, never documented or read. Removed from the signature and the `df.ta` stub; like other unknown keywords it now lands in `**kwargs`.
* **BREAKING — `df.ta.constants()`, `ta.get_time`, `ta.EXCHANGE_TZ` and `ta.CDL_PATTERN_NAMES`**: deprecated in 0.8.32 (`FutureWarning` for the first three, `DeprecationWarning` for the last). Horizontal chart lines and wall-clock/exchange-timezone helpers are out of scope for a technical-analysis library. Add constant columns directly (`df["0"] = 0`) and use `ta.ALL_PATTERNS`. `pandas_ta_classic.utils.get_time` stays as the internal Strategy run timer. The example notebooks no longer call the removed names.
* **BREAKING — built-in data fetching: `df.ta.ticker()`, `ta.yf()`, `ta.av()` and `pandas_ta_classic.utils.data`** (split from #142): deprecated with a `FutureWarning` in 0.8.32. Data fetching is out of scope for a technical-analysis library. Fetch OHLCV with yfinance or alpha-vantage directly and pass the DataFrame in; `examples/fetch_market_data.py` shows both. Also removed: the `data` optional extra (`integration` now aliases `backtest` only), the `yfinance` / `alpha-vantage` entries in `Imports`, their mypy overrides, and `tests/test_utils_data_alphavantage.py`. The VectorBT example notebook now downloads with `yfinance` directly.
* **BREAKING — `drift` parameter removed from `tsignals`, `cfo`, `inertia`, `kst`, `rsx`, `chop`, `accbands` and `kvo`** (issue #138): deprecated in 0.8.32, where passing it emitted a `DeprecationWarning` and the value was ignored. The parameter is now gone from the function signatures and the `df.ta` stubs. Because every indicator takes `**kwargs`, an existing `drift=` call keeps running and the value still has no effect; it only stops warning. Remove the argument. `tsignals` always uses a 1-period difference.
* **`AVG_PERIOD`** (`candles/_cdl_math.py`): dead constant; its only consumer was removed in the 0.8.32 dead-code audit (leftover from #142).

### Fixed
* **`nvi`, `pvi` and `vp` cleared `DatetimeIndex.freq` on the caller's own index**: each selected a subset with a boolean mask (`signed_volume[signed_volume < 0]`) and multiplied it back against a full-length Series. Realigning the subset rebuilds the index, and pandas clears the frequency on the shared index object, so `df.ta.nvi()` unset `df.index.freq` even with `append=False` — and the next `df.index.freq` read `None` for reasons nothing in the call suggested. All three use `.where()` now, which keeps the full index. Their values are unchanged (bit-identical on random OHLCV, same NaN mask). A generic sweep in `tests/test_index_contract.py` now calls every registered indicator on its own frame and asserts that each input Series comes back untouched — same index object, `freq`, labels, name, dtype and values — because `index.equals()` ignores `freq` and the existing output-index sweep could not see this class of bug. The same check runs over the `df.ta.<name>()` accessor path, where the loss was visible to users, both with the default `append=False` and with `append=True`, which may add columns but must leave the index and the input data alone. `df.ta.strategy()` is covered the same way (all, a category and a custom strategy, serially and on workers): it may only append columns. Serially it cleared the frequency, on workers it did not, which is why the loss depended on how the strategy ran.
* **BREAKING — a leading NaN run changed the result of 17 indicators**: chained input (one indicator's output fed into another) starts with a NaN warm-up run. `rsx` then stuck at 50.0 on every bar, `ha` returned all NaN, `sarext` returned all NaN, `aroon`, `maxindex`, `minindex`, `minmaxindex`, `entropy`, `psl`, `msw` and `ebsw` published values on windows that were still filling, `obv`/`aobv` were offset by the first bar's volume, `kvo` dropped rows, and `psar`, `qqe` and `supertrend` differed on their first bars. They now skip the leading NaN run like the 14 indicators that already did, so the result over the real bars equals the result on the clean series. Clean input is unchanged (all 281 default outputs hash identically). `tests/test_leading_nan_contract.py` checks every registered indicator.
* **BREAKING — chain mode followed `df.copy()` and slices**: `df.ta.chain()` stored its flag in `df.attrs`, which pandas copies, so `df.copy().ta.rsi()` or `df.iloc[-100:].ta.rsi()` returned the whole DataFrame and appended to it. Chain mode now applies only to the DataFrame `chain()` was called on.
* **BREAKING — `total_time` mixed calendar days with trading days per year**: `total_time(df, "years")` divided the span's calendar days by 252 trading days, so one calendar year reported 1.448 years and every annualised metric was wrong. It now derives every unit from `total_seconds()`, so `"years"` uses 365.25 calendar days per year and `"days"`/`"hours"` no longer truncate sub-day spans (a 6.5-hour frame is 0.271 days, not 0). Affected: `df.ta.time_range` (years), `cagr`, `volatility`, `sharpe_ratio(use_cagr=True)`, `sortino_ratio`, `calmar_ratio` and `downside_deviation`. A series that doubles over one calendar year now reports a ~100% CAGR instead of ~61%.
* **BREAKING — `trima` built a triangle one bar too wide for even lengths**: the second SMA window used `length // 2 + 1`, so `length=10` computed `SMA(SMA(close, 6), 6)` (an 11-bar window) instead of TA-Lib's `SMA(SMA(close, 6), 5)`. The second window is now `(length + 1) // 2`; even lengths match TA-Lib to machine precision.
* **BREAKING — native `sarext` diverged from TA-Lib `SAREXT`**: the loop kept the projected SAR for the old direction on a reversal, so it reversed on every bar; it also applied `offsetonreverse` towards price instead of away from it, ignored the sign of `startvalue` (which sets the first direction in TA-Lib), and clamped the first projection with bar 0 instead of bar 1. The native path is now TA-Lib's state machine and matches `SAREXT` exactly for every parameter.
* **BREAKING — `cross(above=False)` and `cross_value(above=False)` fired on NaN and ties**: the below-cross used `~current & ~previous`, which is not the mirror of the above-cross and fired on every NaN, tie and bar-0 bar. Both crosses are now strict transitions (above: "was at-or-below, now above"; below: "was at-or-above, now below") and ignore NaN.
* **BREAKING — `supertrend` ratcheted only the active band**: the `SUPERT` stop level used the active band and reset at flips, while the cited source and TradingView ratchet both final bands on every bar with an **or** condition. The loop now ratchets both; the direction signal is unchanged.
* **BREAKING — `cpr` weekly, monthly and intraday levels came from the wrong period**: `resample("W")`/`resample("M")` label each bin at the period end, so the extra `.shift(1)` read the period before last, and `resample("D")` created empty weekend bins, so every Monday read NaN. Dropping the shift instead would have let a bar on the period's last day read its own period (look-ahead). Each bar now reads the last completed calendar day, week (Monday to Sunday) or month before its own, whatever the bar frequency; periods with no bars are skipped.
* **BREAKING — `dm` column names collide with `adx`**: `dm` published smoothed +DM/−DM as `DMP_14`/`DMN_14`, the same names `adx`/`adxr` use for +DI/−DI, so `strategy("All")` overwrote +DI with +DM. `dm` now returns `PLUS_DM_14`/`MINUS_DM_14`, matching the standalone `plus_dm`/`minus_dm`.
* **BREAKING — `stochrsi(talib=True)` ignored `k` and `rsi_length`**: TA-Lib `STOCHRSI` folds the %K range and smoothing into one period and cannot express `k > 1`, so the branch now only runs when `k == 1` and passes `timeperiod=rsi_length`, `fastk_period=length`, `fastd_period=d`; any other `k` or `mamode` runs natively.
* **BREAKING — `jensens_alpha` returned NaN and `pure_profit_score` always returned 0**: the linear-regression guard `int(x.sum()) != 0` skipped any benchmark whose returns summed to less than 1 in absolute value, and `pure_profit_score` built its time index as a constant series of zeros. The guard is now `x.std() != 0` and the index is `0, 1, 2, …`.
* **BREAKING — `bop` returned +1.0 on a flat bar and `non_zero_range` downcast epsilon on int64 prices**: a flat bar gave `epsilon / epsilon = 1.0` (TA-Lib: 0), and on int64 prices the float epsilon was silently downcast to 0, so `ad`/`adosc`/`bop`/`cmf` produced NaN. `bop` now returns 0 on a flat bar and `non_zero_range` casts integer input to float before substituting epsilon.
* **BREAKING — column resolution took the first case-insensitive prefix match**: `df.ta.bop()` on Binance-style columns resolved `open` to `Open time` (epoch milliseconds). `_get_column` now falls back to a case-insensitive exact match only.
* **BREAKING — the accessor returned the caller's whole DataFrame when an input was missing**: seven indicators handed back the source frame, so "nothing was produced" was indistinguishable from a result without comparing object identity — the problem `mavp` already calls out in its own guard. Six of them now return `None`: `beta` and `correl` without a `benchmark`, `long_run` and `short_run` without `fast`/`slow`, `tsignals` without a `trend`, and `xsignals` without a `signal`. The seventh, `ma`, computes instead: its `source` maps to the close column, so `df.ta.ma()` dispatches to the default EMA (`ta.ma()` still lists the available MA names). `_post_process` returns `None` for a missing input instead of `self._df` — in chain mode too, because continuing the chain on a frame that gained no column would hide the failure for the rest of it. Every other indicator is unaffected: 217 of 224 outputs and `cdl_pattern("all")` hash identically before and after, with numba and with `NUMBA_DISABLE_JIT=1`.

### Performance
* **The six `ht_*` indicators are about 110x faster** (last-bit differences on Linux, see below): `cycles/_hilbert.py` `_hilbert_transform_loop` is a per-bar Python loop shared by `ht_dcperiod`, `ht_dcphase`, `ht_phasor`, `ht_sine`, `ht_trendline` and `ht_trendmode`, and it dominated every run that touched the cycles category — 72% of a serial `df.ta.strategy("all")`. It now carries `@njit(cache=True)`, like the 87 other hot loops in the package: 1.66 s to 0.015 s on 100,000 rows on Windows (1.27 s to 0.016 s on Linux), and `strategy("all")` serial 14.3 s to 3.7 s (11.3 s to 2.9 s). Every other indicator is untouched: all 224 indicator outputs and `cdl_pattern("all")` hash identically before and after on both platforms, with numba and with `NUMBA_DISABLE_JIT=1`, as do 98 Hilbert edge cases (interior NaN, leading NaN, +/-inf, +/-0.0, constant, empty, all-NaN, 1e308, 5e-324). Without numba installed, or with `NUMBA_DISABLE_JIT=1`, the decorator is the existing no-op and results are bit-identical to before on every platform.

  With numba active on Linux, `ht_dcperiod`, `ht_dcphase`, `ht_phasor` and `ht_sine` change in the last bits. numba compiles `np.arctan` to the platform `atan` (bit-identical to `math.atan`), while numpy uses its own implementation, and on glibc the two differ by one unit in the last place for 0.11% of inputs (214 of 200,000 samples, at most 2.2e-16 absolute); the `period` recursion then carries that forward. Measured on the bundled sample data with numpy 2.5.3 on both platforms: at most 7.8e-16 relative for `HT_DCPERIOD` and 4.9e-14 for `HT_SINE`, with no NaN moving; `ht_trendline` and `ht_trendmode` are unchanged, and so is every value on Windows, where numpy's `arctan`, `math.atan` and numba agree exactly. `np.sin`, `np.cos` and the phase lookup tables are bit-identical on both platforms, the difference is independent of numpy's AVX-512 dispatch, and the TA-Lib oracle comparisons pass unchanged.

### Changed
* **Short-window hardening in `rma`, `linreg` and `_sliding_weighted_ma`**: all three assumed the `verify_series` `min_length` guard had already rejected a window longer than the series — `rma` seeded at `close.iloc[length - 1]`, and the other two built a `sliding_window_view` wider than the input array. No route to any of them was found through the public API, so this changes no observable behaviour; it is defence in depth, prompted by the `ema` seeding bug (see Fixed), which was equally unreachable until a particular composition of indicators exposed it. `min_length` models a single window while real lookback is compositional, so it cannot rule out the next such case. All three now return an all-`NaN` Series when no full window fits, matching `statistics/variance.py` and `_sliding_argextreme`.
* **`td_seq` ~3500× faster (numba)**: the Tom DeMark Sequential consecutive-run count replaced `rolling(13).apply(python_callback)` with a numba `@njit` loop (`~1912 ms` → `~0.5 ms` per 5000-bar call, the single largest indicator bottleneck). Bit-for-bit identical; falls back to a plain Python loop without numba. Reproduce with `python tools/bench_indicators.py`.
* **`hilo` ~250× faster (numba)**: the Gann HiLo per-bar `.iloc[]` state loop moved into a numba `@njit` kernel over numpy arrays (`~130 ms` → `~0.5 ms` per 5000-bar call). Output is identical for all `mamode`s; falls back to a plain Python loop without numba.
* **`jma` ~130× faster (numba)**: the Jurik Moving Average per-bar recursion (volatility bands + 3-stage filter) moved into a numba `@njit` loop with scalar coefficients precomputed by the caller (`~50 ms` → `~0.4 ms` per 5000-bar call). The trailing-window average uses `np.mean` in place of the original `np.average`; for an unweighted call numpy computes these bit-for-bit identically, so the **numba-off fallback is bit-identical to the previous output**. Under numba (JIT on), `np.mean` compiles to numba's own reduction, whose summation order differs from numpy's at the ULP level (~4e-16 relative, full float64 precision); compounded through the recursive `jma[i] = jma[i-1] + det1` update the JIT path lands within ~1 ULP of the original but not bit-for-bit identical. Inconsequential for any practical use; `jma` is the only optimised indicator here whose JIT and numba-off paths are not bit-identical to each other (every other one is).
* **`ha` ~50× faster (numba)**: the recursive Heikin-Ashi open (`df.iat[]` scalar loop) moved into a numba `@njit` scan over the precomputed HA_close array (`~75 ms` → `~1.5 ms` per 5000-bar call). Output is identical; falls back to a plain Python loop without numba.
* **`stc` ~40× faster (numba)**: the two Schaff Trend Cycle stochastic-smoothing loops moved into a shared numba `@njit` kernel, parametrised by the gate series (pass 1 gates on the rolling minimum, pass 2 on the rolling range) (`~82 ms` → `~2 ms` per 5000-bar call). Output is bit-for-bit identical (the cumulative 8-decimal rounding is preserved inside the kernel); falls back to a plain Python loop without numba.
* **`wad` ~15× faster**: Williams A/D replaced `Series.combine(prev_close, max/min)` (a per-element Python callback) with vectorised `np.fmax`/`np.fmin` (`~16 ms` → `~1 ms` per 5000-bar call). Output is identical; pure numpy, no numba needed.
* **`wilder_smooth` / `dm` ~5× faster (numba)**: Wilder's cumulative smoothing (`utils/_wilder.py`, used by `dm`) moved its per-bar recursion into a numba `@njit` kernel. The seed (`np.nansum(raw[1:length])`) is still computed with numpy in the caller and passed in, so the cumulative sum matches bit-for-bit — the kernel runs only the deterministic scalar recursion. `dm` `~10.5 ms` → `~2.0 ms` per 5000-bar call. Bit-for-bit identical; falls back to a plain Python loop without numba.
* **`pmax` ~4.6× faster (numba)**: the PMAX adaptive-band / trend-direction per-bar loop is now `@njit`-compiled with its Python-list accumulators replaced by numpy arrays (`~5.4 ms` → `~1.2 ms` per 5000-bar call; the residual is the ATR/MA prep). The loop is pure comparisons + `min`/`max` + assignment, so output is bit-for-bit identical; falls back to a plain Python loop without numba.
* **`npround` ~400× faster (vectorised)**: replaced the per-element `close.apply(np.round)` Python callback with a single vectorised `np.round(close)` (`~6 ms` → `~0.02 ms` per 5000-bar call). Output is bit-for-bit identical.
* **`aroon`, `maxindex`, `minindex`, `minmaxindex` ~9–17× faster (vectorised)**: the rolling `argmax`/`argmin` arg-position loops (`Series.rolling(length).apply(np.argmax/argmin, raw=True)`) now use a shared `_sliding_argextreme()` helper built on `numpy.lib.stride_tricks.sliding_window_view` (mirrors the existing `_sliding_weighted_ma`). aroon `~12 ms` → `~0.7 ms`, minmaxindex `~8 ms` → `~0.8 ms`, maxindex/minindex `~4 ms` → `~0.4 ms` per 5000-bar call. Integer arg-positions → bit-for-bit identical output; pure numpy, no numba needed.
* **`ebsw` ~850× faster (numba)**: the Even Better SineWave per-bar `.iloc[]` HighPass + SuperSmoother recursion moved into a numba `@njit` kernel over a numpy array, with the (bar-invariant) filter coefficients hoisted out of the loop and the 2-element `FilterHist` list replaced by two scalars (`~34 ms` → `~0.04 ms` per 5000-bar call). Output is bit-for-bit identical; falls back to a plain Python loop without numba.
* **`kama` ~90× faster (numba)**: Kaufman's Adaptive MA per-bar smoothing recursion moved into a numba `@njit` loop over numpy arrays (the vectorised efficiency-ratio/smoothing-constant prep stays in pandas) (`~30 ms` → `~0.3 ms` per 5000-bar call). Output is bit-for-bit identical; falls back to a plain Python loop without numba.
* **`mama` ~55× faster (numba)**: the MESA Adaptive MA / FAMA inline Hilbert-Transform loop is now `@njit`-compiled (`~16 ms` → `~0.3 ms` per 5000-bar call). Output is bit-for-bit identical (verified against the pure-Python `.py_func`); falls back to a plain Python loop without numba.
* **Candlestick patterns ~32× faster (numba)**: all 60 native `cdl_*` pattern per-bar detection loops (the TA-Lib incremental running-window algorithm) moved into numba `@njit` kernels over numpy arrays, with the average-factor constants and range arrays hoisted by the caller. `cdl_pattern(name="all")` drops from `~288 ms` to `~9 ms` per 5000-bar call. Output is bit-for-bit identical for every pattern; falls back to a plain Python loop without numba.
* **Faster cold import (~3–4×)**: `import pandas_ta_classic` takes ~280 ms (was ~930 ms) because indicator functions load on demand. Attribute access is unchanged — `ta.sma`, `ta.rsi`, `ta.cdl_doji`, `ta.momentum` and friends all still resolve, now through the module's `__getattr__` (PEP 562) instead of eager binding. See the star-import entry below for the one case that did change.
* **BREAKING — `from pandas_ta_classic import *` no longer binds the indicator functions**: the eager `from pandas_ta_classic.<category> import *` chain in `core.py` used to leak every indicator into the top-level module dict, so a wildcard import bound ~427 names, `sma` and `rsi` among them. With on-demand loading they resolve through `__getattr__` and are therefore absent from `__all__`, so `from pandas_ta_classic import *; sma(df["close"])` now raises `NameError`. This is deliberate: listing all ~250 indicators in `__all__` would work and would even stay lazy for everyone else, but it would also bind `math`, `statistics`, `min`, `max` and `sum` into the importer's namespace, shadowing the stdlib modules and builtins of those names — which is exactly why `_lazy_subpackage.py` keeps those aliases out of `__all__` in the first place. Use the documented form instead: `import pandas_ta_classic as ta`, then `ta.sma(...)`, or import the function directly with `from pandas_ta_classic.overlap.sma import sma`. Wildcard imports of a 250-function library were never a good idea; this makes that explicit rather than silently supported. (The related regression where `ta.momentum`, `ta.overlap`, `ta.trend` et al. raised `AttributeError` was *not* intentional and is fixed — see Fixed, below.)
* **Math operators individually importable**: Each math/trig operator (`add`, `sub`, `mult`, `div`, `rolling_max/min/sum`, `acos`, `cos`, `exp`, `ln`, …) now lives in its own submodule, e.g. `from pandas_ta_classic.math.add import add`.
* **`combination()` delegates to `math.comb`**: Replaces the hand-rolled nCr loop. Signature and results unchanged; the unused `multichoose` kwarg alias was dropped (use `repetition`).
* **`npNaN` alias removed internally**: All modules now use `np.nan` directly. No public API change.
* **All `npX` numpy import aliases removed** (26 aliases, e.g. `npSqrt`, `npArange`, `npNdArray`): modules now use `import numpy as np` + `np.x` directly. Internal only; no public API change.
* **Explicit package namespace**: `pandas_ta_classic/__init__.py`, `core.py`, and `utils/__init__.py` no longer use star imports — every re-export is explicit with `__all__` defined. All documented names (utility functions, metrics, `Strategy`, lazy-loaded indicators) are unchanged. Incidental namespace leaks (e.g. `ta.np`, `ta.pd`, `ta.DataFrame`, `ta.logger`) are gone; import these from their real homes.
* **Lint-clean repo**: Ambiguous variables renamed (`O` → `O_` in candle loops, `l` → `low` in tests); `sys.path` bootstrap hacks removed from `tests/fixtures/`, `tools/`, and `docs/conf.py` (the editable install makes them redundant); notebook cells reordered to import-first.
* **`linear_regression()` always uses the numpy implementation**: the `"r"` key is now consistently the Pearson correlation coefficient. Previously, environments with scikit-learn installed silently used `LinearRegression.score()` (R²) instead, so results depended on the environment. Affects `pure_profit_score`.
* **`optimal_leverage()` returns a float**: the result is no longer truncated with `int()`, the `capital` argument is documented, the unused `**kwargs` parameter is removed, and the "Incomplete. Do NOT use" docstring warning is removed. Zero-variance input now raises `ValueError` (previously crashed with `OverflowError`).
* **Optional-dependency extras restructured**: the `integration` extra is split into `data` (`yfinance`, `alpha-vantage` — the only integrations the library imports, lazily via `utils/data`) and `backtest` (`backtesting`, `vectorbt`, `backtrader` — docs/examples only). `integration` is retained as an alias for `data,backtest`. The `[all]` extra no longer pulls `data`/`backtest`, so `pip install "pandas-ta-classic[all]"` stays installable on newer Python/OS combinations that lack wheels for these unmaintained, platform-fragile packages; install them explicitly when needed.
* **tulipy oracle frozen to a golden file**: `tulipy` (unmaintained, no wheels for CPython ≥3.12) is removed from the `oracle` extra and no longer imported at test time. Its deterministic outputs are snapshotted in `tests/fixtures/tulipy_oracle.json` (regenerate with `tests/fixtures/generate_tulipy_oracle.py` on CPython <3.12), and `test_oracle_tulipy.py` now compares native output against the frozen arrays on **every** Python version. This fixes the `testing-oracle` CI job on Python 3.12–3.14, where the tulipy install previously failed. `ta-lib` remains the live primary oracle. (The MSW oracle tolerance was loosened to `1e-3` to stay robust to ~`1e-4` numpy-version float drift in that recursive trig indicator.)
* **`tal_ma()` no longer needs TA-Lib and fails fast**: the MA-name→`MA_Type` mapping is now a plain dict of the (frozen) TA-Lib enum values, so `tal_ma("ema") == 1` regardless of whether TA-Lib is installed (previously it silently returned `0`/SMA when TA-Lib was absent). Unknown names now raise `ValueError` and non-string input raises `TypeError` instead of silently defaulting to SMA. Callers (`bbands`, `ppo`, `apo`) already normalise `mamode` to a valid string, so their behaviour is unchanged.

### Deprecated
* **Passing a non-Series where an indicator expects a Series** (issue #145): a list, numpy array, DataFrame or scalar used to make `verify_series()` return `None` silently, so `ta.sma(df['close'].values)` returned `None` and `df.ta.sma(close=df['close'].values)` added nothing — the mistake surfaced, if at all, as an unrelated error several frames later (backtesting.py #342, #1243). It now emits a `FutureWarning` naming the indicator and the type received, attributed to the calling line, and still returns `None`; a future release will raise `TypeError`. A Series shorter than the indicator's window and an omitted optional argument (`None`) are unaffected and still return `None` without a warning.
* **Built-in data fetching (`df.ta.ticker()`, `ta.yf()`, `ta.av()`)**: emit a `FutureWarning` and will be removed in a future release. Data fetching is out of scope for a technical-analysis library. Fetch OHLCV with `yfinance` / `alpha-vantage` directly and pass the DataFrame to pandas-ta-classic; see the new `examples/fetch_market_data.py` for the replacement patterns. The `data` optional extra remains available during the deprecation window.
* **`ichimoku()` tuple return**: returning a `(visible, span)` tuple is deprecated and now emits a `DeprecationWarning`. Pass `as_dataframe=True` to migrate now (add `append_span=True` for the projected span rows). `as_dataframe=False` keeps the tuple and silences the warning for now, but it is deprecated too and will be removed together with the tuple return. The accessor `df.ta.ichimoku()` already returns a DataFrame and is unaffected.
* **`CDL_PATTERN_NAMES`**: Use `ALL_PATTERNS` instead. Accessing the old name emits a `DeprecationWarning`.
* **`tsignals` `drift` parameter**: Passing `drift` now emits a `DeprecationWarning` and the value is ignored — trade signals are always computed with a 1-period difference. The parameter will be removed in a future release.
* **Inactive `drift` parameters on `cfo`, `inertia`, `kst`, `rsx`, `chop`, `accbands`, `kvo`**: These indicators accepted a `drift` parameter that never entered their calculation (dead since the upstream template). Passing `drift` now emits a `DeprecationWarning`; the value has never affected the result and the parameter will be removed in a future release. Misleading docstrings were corrected (e.g. `cfo`'s "short period", `chop`'s `ATR(drift)` pseudocode).

### Fixed
* **Short input crashed four indicators instead of returning `None`** (issue #145): `pvt` with `drift` longer than the input and `swma(length=1)` raised `TypeError: unsupported operand type(s) for *: 'NoneType' and 'float'`, `rvi(length=1)` on fewer than 30 rows raised the same (its `stdev` returned `None`), and `tos_stdevall` on one row raised `LinAlgError` from a one-point linear fit. `symmetric_triangle(1)` now returns `[1]`, so `swma(length=1)` equals its input. A sweep of every indicator over 1–400 rows with `length`, `drift`, `fast`, `slow` and `signal` at their smallest values now finds no crashes.
* **Tests broke on TA-Lib 0.8.0** (`tests/test_indicator_momentum.py`): `test_apo`/`test_ppo` compared the SMA-based `apo`/`ppo` against `talib.APO(close)`/`talib.PPO(close)` with TA-Lib's default `matype`, which TA-Lib 0.8.0 changed from 0 (SMA) to 1 (EMA). The oracle calls now pass `matype=0` explicitly. Library behaviour is unchanged: `apo`/`ppo` default to SMA, and `talib=True` already passes `matype` explicitly.
* **14 indicators returned all-`NaN` on chained input**: `adosc`, `fisher`, `hwc`, `hwma`, `jma`, `kama`, `lrsi`, `macd` (and `macdfix`), `mama`, `mcgd`, `ssf`, `tos_stdevall` and `vidya` seed a recursion (or fit) from the first bar, so a leading `NaN` run — what every indicator's output starts with — turned the entire result `NaN`. A shared `skip_leading_nan` decorator (`utils/_core.py`) now computes them on the rows after that run and pads the result back to the input index; the output past the prefix equals the output on the trimmed series, and `kama`, `mama` and `adosc` match TA-Lib with a prefix. Input without a leading `NaN` run is unchanged.
* **`ht_*` reported values TA-Lib does not, and `ht_trendmode` invented a trend mode for undefined bars**: the native Hilbert Transform emitted values inside TA-Lib's lookback (32 bars for `ht_dcperiod`/`ht_phasor`, 63 for `ht_dcphase`/`ht_sine`/`ht_trendline`/`ht_trendmode`) from a recursion that had not converged — `ht_dcperiod` returned `0.0` for its first 12 bars. Those bars are now `NaN`, and all six indicators match TA-Lib's `NaN` positions and values, with or without a leading `NaN` run. After a mid-series `NaN`, `ht_trendmode` returned `0` ("cycle mode") for every remaining bar; those undefined bars are now `NaN` (the result is float-typed in that case; fully defined input keeps the int dtype, and the lookback still reports `0` as TA-Lib does).
* **`adx`, `adxr`, `dx`, `plus_dm`, `minus_dm` diverged from TA-Lib in their first bars**: `rma` seeded on `iloc[0:length]` even when that window began with `NaN`, which chained input (DM series, true range, `dx`) always does, so the seed averaged a partial window; and the ADX family smoothed DM/TR with that SMA-seeded `rma` where TA-Lib uses Wilder's running sum of the first `length - 1` values (`utils/_wilder.py`, already used by `dm`). On SPY, `ADX_14` was up to 49.7% off `talib.ADX` and started 14 bars early. `rma` now seeds after the leading `NaN` run, `wilder_smooth` skips a leading `NaN` run too, `true_range` leaves the first bar after a leading `NaN` run undefined (it has no previous close; `max(axis=1)` used to turn it into `high - low`), and the ADX family uses Wilder seeding: all seven outputs match TA-Lib bit-for-bit in position and to ~1e-15 in value. Side effects, all toward TA-Lib: `rsi`, `atr` and `natr` no longer emit one value at bar `length - 1` computed from `length - 1` changes (first value now at bar `length`, as TA-Lib), and indicators built on them (`aberration`, `ce`, `cksp`, `kdj`, `pgo`, `pmax`, `qqe`, `stochrsi`, `supertrend`) start one or two bars later. Last values are unchanged; frozen fixtures regenerated.
* **`df.ta.adjusted` had no effect**: the property was stored (and, since the pandas 3 fix, persisted) but never read — every indicator wrapper passed the literal `"close"` to the column lookup, so `df.ta.adjusted = "adj_close"; df.ta.sma(length=10)` still averaged `close`. Indicators that default to the close column (including `series_a`/`series_b` defaults and `df.ta.ichimoku()`) now read the adjusted column, as `docs/dataframe_api.rst` documents. An explicit `close="col"` still wins; `high`, `low`, `open` and `volume` are unaffected; `df.ta.adjusted = None` restores `close`.
* **Accessing `df.ta` wrote into the caller's `DataFrame.attrs`**: `AnalysisIndicators.__init__` stored `_ta_last_run` on every access, so merely touching `df.ta` mutated the frame and the key propagated to derived frames and Parquet metadata. Nothing is written until `df.ta(kind=...)` or `df.ta.strategy()` runs; `df.ta.last_run` is `None` before that (it used to report the accessor's construction time, which looked like a run that never happened).
* **Native candle patterns went silent on chained input**: `run_pattern` (`candles/_cdl_math.py`) built its running body/shadow averages from the first bar, so a leading NaN run — what every chained indicator produces — made every later average `NaN`, every comparison `False`, and every signal `0`. With a 30-bar NaN prefix on 600 SPY bars, 33 of 62 `cdl_pattern` columns were all-zero (`CDL_3INSIDE` 0 signals, TA-Lib 10). The patterns now start at the first bar with all four prices finite, as TA-Lib does; all 62 columns match TA-Lib bar for bar with and without a prefix. Output for NaN-free input is unchanged.
* **Lookahead-bias test suite** (`tests/test_lookahead.py`): every registered indicator is evaluated over the full series and over two prefixes, and the shared bars must match exactly. The synthetic frame plants flat bars, zero-volume bars, a constant-price run and an extreme bar past the last cut point, since a batch-global branch is only visible when its trigger is in the data (issue #149 was invisible on the SPY sample data, which has no flat bar). Each boolean keyword is additionally flipped one at a time, which is what catches a leak behind a non-default flag such as the old `cdl_z(full=True)`. Each call is its own parametrised case; the ones that look forward on purpose (`dpo` unless `centered=False`, `ichimoku` unless `include_chikou=False`, `tos_stdevall`, `vp`, `cpr(virgin_cpr=True)`) are marked `xfail(strict=True)`, so an exemption cannot go stale in either direction -- an unmarked call that leaks fails, and a marked call that has become causal fails as XPASS.
* **`tos_stdevall()` and `vp()` now decline `lookahead=False` instead of ignoring it**: `df.ta.strategy()` forwards keyword arguments to every indicator, so `df.ta.strategy("all", lookahead=False)` used to hand back three `TOS_STDEVALL_*` columns fitted over the whole series — a caller who asked for backtest-safe output silently got output that is not. Neither indicator has a causal mode to switch to, so both now emit a `UserWarning` and return `None`. The strategy run drops from 402 to 395 columns and the remaining ones are all causal. Calls without `lookahead=False` are unaffected.
* **`cpr()` silently ignored `lookahead=False`**: `dpo()` and `ichimoku()` honour that keyword as the library-wide opt-out from forward-looking output, but `cpr(virgin_cpr=True, lookahead=False)` returned the same forward-looking `CPR_VIRGIN` column as without it — a caller who had learned the convention got lookahead data while believing they had opted out. `lookahead=False` now forces `virgin_cpr` off. The default call is unaffected. `test_lookahead_false_is_all_or_nothing` derives which indicators must honour the keyword (those that already have a causal mode) instead of assuming it, so a future indicator with a switchable forward-looking branch cannot skip it.
* **BREAKING — `mavp` now requires `periods`; the length-dependent default is gone (issue #149 follow-up)**: when `periods` was omitted it defaulted to `linspace(minperiod, maxperiod, len(close))`, so every bar's window length was a function of how many bars were passed in and appending data changed already reported values. `periods` is now a **required** input, as it is in TA-Lib, and has no default at all, so omitting it is a `TypeError` that type checkers catch. `df.ta.mavp()` raises `ValueError`, because the accessor fills missing required arguments with `None` and would otherwise return the source DataFrame unchanged. `mavp` is excluded from `df.ta.strategy()`'s default indicator set for the same reason `tsignals` and `xsignals` are.
* **`cdl_z(full=True)` returned a constant column built from future data (issue #149 follow-up)**: it set the rolling window to `close.size` — so only the final bar had a value — and then `bfill()`ed, copying that single value onto every earlier row. `full=True` now computes an anchored (expanding) Z Score: each bar is standardised against bars `0..t` only. The first bar has no standard deviation and stays `NaN`; column names are unchanged.
* **`non_zero_range` leaked future bars into earlier rows (issue #149)**: the epsilon substitution for zero-range bars was applied to *every* row as soon as *any* row in the batch had `high == low`, so appending a single flat bar shifted the whole computed history and batch evaluation disagreed with streaming evaluation. The epsilon is now applied pointwise, to the flat rows only. 27 indicators inherited the leak — `aberration`, `accbands`, `ad`, `adosc`, `adx`, `adxr`, `atr`, `bop`, `brar`, `ce`, `chop`, `cksp`, `cmf`, `emv`, `eom`, `kc`, `marketfi`, `massi`, `natr`, `pdist`, `pgo`, `pmax`, `qstick`, `rvgi`, `supertrend`, `true_range`, `vortex` — and are all causal again. `kama` and `stc` also call `non_zero_range` and changed too (they were missing from this list when 0.8.32 shipped), as can `bbands`, `cdl_doji`, `dx`, `fisher`, `kdj`, `stoch`, `stochf`, `stochrsi` and `vhf` on input where the range they pass is exactly zero. On inputs that contain such a zero, values change by a few ULP for most indicators and by up to 1.5e-6 in `stc` (about 1e-8 relative to its 0–100 scale); they are unchanged otherwise.
* **`df.ta.indicators()` printed nothing** (issue #152): the default (non-`as_list`) call wrote its report via `logger.info()`, and the package installs a `NullHandler`, so users saw no output unless they configured logging themselves. It now prints to stdout again. The return value is unchanged (`None` unless `as_list=True`).
* **Installation-verification snippet in the docs raised `TypeError`** (issue #152): `docs/installation.rst` called `len(df.ta.indicators())`, but the default call returns `None`. Corrected to `len(df.ta.indicators(as_list=True))`.
* **`ta.<category>` attribute access was order-dependent**: `momentum`, `overlap`, `trend`, `volume`, `statistics`, `candles`, `cycles`, and `math` raised `AttributeError: module 'pandas_ta_classic' has no attribute '<category>'` on a fresh import, and only started working after something else happened to import that category subpackage as a side effect (e.g. calling `df.ta.rsi()` before touching `ta.momentum`) — an artifact of Python's import machinery binding submodules onto their parent only on first import, which the lazy-loading `__init__.py` didn't otherwise trigger. All 10 category subpackages (`candles`, `cycles`, `math`, `momentum`, `overlap`, `performance`, `statistics`, `trend`, `volatility`, `volume`) now resolve deterministically via the module's `__getattr__` (PEP 562) and are advertised by `dir(pandas_ta_classic)` without requiring prior access. They stay out of `__all__`, which lists the eagerly bound names, so `from pandas_ta_classic import *` is unchanged. Cold-import time is unaffected — the category subpackages still load only on first access, not at `import pandas_ta_classic` time; `volatility` in fact no longer loads eagerly, since the `from . import volatility` that used to force it is redundant now that `__getattr__` resolves every category (the shadowing invariant it guarded is enforced in `utils/__init__.py`, which keeps the `utils.volatility()` metric out of `utils.__all__`). `docs/quickstart.md`'s "List indicators by category" example was also corrected to `ta.Category["momentum"]` etc., since `print(ta.momentum)` only ever printed a module repr, not the indicator list.
* **`ta.cdl` raised `AttributeError`**: the shorthand candle-pattern wrapper lives inside `candles/cdl_pattern.py` rather than a `cdl.py` of its own, so it is not a `Category` entry and no `__getattr__` branch resolved it once the categories stopped being imported eagerly. It is back, is the same object as `ta.candles.cdl`, and now appears in `dir(pandas_ta_classic)`. `ta.cdl_pattern` and `df.ta.cdl_pattern` were unaffected; `df.ta.cdl` never existed.
* **`tsignals` `drift` corrupted trade signals**: `trends.diff(drift)` computed entries/exits against the state `drift` bars ago instead of the previous bar, so `drift != 1` reported spurious entries mid-trend and missed real crossovers (contradicting the documented `diff()` behavior). Now always uses a 1-period difference. Output at the default (`drift=1`) is unchanged.
* **Cross-package indicator imports**: A submodule import could overwrite a re-exported function of the same name on the parent package (e.g. `from pandas_ta_classic.volatility import atr` occasionally returned the `atr` *module* instead of the function). Resolved.
* **All six `ht_*` indicators crashed on a single NaN**: the Hilbert Transform loop rounds the dominant cycle period with `int(smooth_period + 0.5)` (`cycles/_hilbert.py`), and one NaN anywhere in the input poisons the recursion that feeds it, so `ht_trendline`, `ht_dcperiod`, `ht_dcphase`, `ht_sine`, `ht_phasor` and `ht_trendmode` raised `ValueError: cannot convert float NaN to integer`. A NaN prefix is what every chained indicator produces, so this was reachable from ordinary use. A leading NaN run is now skipped and the transform starts at the first finite close, as TA-Lib does, so chained input produces values instead of an all-`NaN` column (matches `talib.HT_*` to ~1e-11 on shared bars). A NaN later in the series still poisons the recursion; bars from there on emit `NaN` instead of raising — as `tests/test_indicator_edge_cases.py` already required. Output for NaN-free input is unchanged (all 119 TA-Lib oracle tests pass).
* **`candle_color` crashed on a NaN open or close**: it built its result with `close.copy().astype(int)` (`utils/_candles.py`), which raises `IntCastingNaNError` because pandas cannot cast NaN to an integer dtype. This propagated out of `cdl_inside` and `cdl_pattern`. A bar with an undefined colour now yields `NaN` — previously it would have kept whatever the cast produced rather than being classified — and the result is float-typed in that case; fully defined input keeps the historical integer dtype.
* **`ema` crashed on chained indicators with clean data and default arguments**: the SMA seed was written to `close.iloc[fv_pos + length - 1]` without checking that the position exists. `verify_series`' `min_length` models a single window, but chained indicators compound their lookback (`trix` applies `ema` three times, so each inner call's NaN prefix pushes the seed further out), so the seed could land past the end of the series and raise `IndexError: iloc cannot enlarge its target object`. This affected 14 indicators over specific row-count ranges — `trix` (30-87 rows), `qqe` (27-70), `tsi` (25-49), `trixh` (18-51), `ppo`/`pvo` (26-33), `rvi`/`pgo` (14-26), `smi` (20-28), `inertia` (20-26), `zlma` (10-13), `efi` (13), `kc`/`thermo` (20) — as well as `df.ta.strategy("all")` on short frames and `bbands(mamode="zlma")`. `ta.trix(pd.Series(range(1, 31), dtype=float))` is the minimal reproducer. When no SMA seed exists the EMA is now all-`NaN`, matching TA-Lib's lookback semantics. Output for inputs that already produced a result is unchanged.
* **`dm` ignored its own short-input contract**: `dm()` called `verify_series(high)` / `verify_series(low)` without `min_length`, so its guard never fired and it returned a DataFrame computed from fewer rows than `length` (default 14). Every sibling indicator (`adx`, `plus_dm`, `minus_dm`) returns `None` there. `dm` now does too. Output for sufficiently long input is unchanged.
* **`cdl_pattern` raised `AttributeError` on short input**: the `doji`/`inside` branch read `pattern_result.name` without checking for `None`, so a sub-pattern that could not be computed (`cdl_doji` needs 10 rows) crashed the whole call with `AttributeError: 'NoneType' object has no attribute 'name'` — via `df.ta.cdl_pattern()` as well. Uncomputable sub-patterns are now skipped, matching the native-pattern branch directly below it; if no pattern can be computed the call returns `None` as documented.
* **Test-fixture regen no longer drops `cmo_14` entries** when running tests without tulipy installed. Generators now merge with existing JSON instead of overwriting.
* **Regression snapshots now cover every tracked indicator** (`tests/test_regression.py`): the file asserted a hand-written list of 43 fixture keys while `regression_snapshots.json` stored 223 — 180 snapshots were generated and never checked, including 55 of the 57 indicators that have no independent oracle and are protected by their snapshot alone. Test methods are generated from the snapshot keys, so the asserted set cannot drift from the stored set again. The duplicated 43-entry `_compute_all` was dropped in favour of the 223-entry one in `test_indicator_values.py`. Checkpoints grew from 5 indices (50–3000) to 24 spanning 50–5221; the previous set left the final 2221 of 5222 rows checked only by the endpoint assertion. Out-of-range checkpoints (`vp`, `tos_stdevall` return shorter series) are now asserted to stay out of range instead of raising `IndexError`.
* **Golden-value tolerance tightened ~10 orders of magnitude** (`tests/assertions.py`): `test_indicator_values.py` and `test_regression.py` shared a duplicated flat `REL_TOL = 1e-4`. They now share one `golden_value_close()` using `|actual - golden| <= 1e-8 + 1e-6 * |golden|`. The absolute term is the `round(v, 8)` storage floor of the JSON files (the old purely relative check had no floor, so small-magnitude columns were checked 220x looser than the file's own resolution); the relative term covers large-magnitude indicators such as `ad` (~3.8e10), where one float64 ULP is already ~7.6e-6. Measured worst requirement across all 423 tracked columns is 3.6e-15. A 3.3e-7 perturbation of the kurtosis adjustment constant passed under the old tolerance and now fails.
* **Statistics golden values come from exact rational arithmetic** (`tests/fixtures/exact_reference.py`): the oracles for `zscore`, `kurtosis`, `skew`, `median`, `quantile`, `mad`, `entropy`, `beta` and `ui` no longer call `pandas` rolling, whose accumulating power sums drift by up to 1.7e-5 across the SPY series and changed between pandas 2.x and 3.x. The reference now evaluates the textbook formula over the exact decimals from the CSV using `fractions.Fraction`. Regenerating produces a byte-identical `expected_values.json`, confirming the previous values were correct. Guarded by `tests/test_exact_reference.py`.
* **Golden fixtures are frozen** (`tests/__init__.py`, `Makefile`): `tests/fixtures/expected_values.json` and `regression_snapshots.json` are no longer regenerated as a side effect of importing `tests/` (or of `make test-all`). Self-regenerating golden files could not detect development errors — a bug rewrote the expectation and the test passed — and imported reference-library floating-point drift, which is why a `pandas` 2.x → 3.x upgrade changed the `kurtosis_20` golden value without any code change. Regeneration is now the explicit `make fixtures` step, whose diff must be reviewed. Test-facing only; no runtime behaviour change.
* **`stoch` returned fewer rows than it was given**: `%K` was smoothed from `stoch.loc[stoch.first_valid_index():]` and never reindexed, so the returned DataFrame was `k - 1` rows short (237 rows for 250 of input at the default `k=14`) and carried an index starting `k - 1` bars into the input. Callers that align the result against the source frame got a silent misalignment; `backtesting.py` rejects the indicator outright (`kernc/backtesting.py#752`: `Indicators must return ... arrays of same length as data`). The warmup bars are now reported as leading `NaN`, as every sibling indicator does — `stochf` already did. Computed values are unchanged, but a positional read (`.iloc[i]`, `.to_numpy()[i]`) now returns bar `i` instead of bar `i + k - 1`; label-based access is unaffected.
* **`t3` returned ~`length` rows short per EMA stage**: `_ema_chain` (`overlap/ema.py`) trims the leading `NaN` off each stage before seeding the next one — correct — but it also handed the *trimmed* stage back to the caller, contradicting its own docstring ("Each result retains the full index of the original *close*"). `t3` combines stages 3–6 arithmetically, so its output lost 18 rows at the default `length=10` (232 rows for 250 of input). Stages are now reindexed to `close` before being returned, so a positional read of `t3` now returns bar `i` instead of bar `i + 18` at `length=10`. `dema` and `tema` were unaffected in length — pandas realigns their two- and three-stage arithmetic to the union index — and all three keep identical values.
* **`td_seq` replaced the input index with a `RangeIndex`**: the consecutive-run counts were wrapped in a bare `Series(...)` around the numba kernel's numpy output, dropping the caller's DatetimeIndex. Row count was right, so the damage was silent: `df["TD_SEQ_UPa"] = ta.td_seq(df.Close)` aligned an integer index against a datetime one and produced an all-`NaN` column. Values are unchanged.
* **`df.ta.strategy()` shipped unreachable columns to every worker**: the multiprocessing "slim" copy sliced the DataFrame on the *pre-run* column count, so a second run pickled the first run's indicators into every task — 1244 MB over the Pool task pipe instead of 18 MB, a 17 MB single write. On Windows that write fails outright with `OSError: [WinError 1450] Insufficient system resources`; on Linux it only wasted time and memory. The worker copy now carries exactly the columns an indicator can reach: the default OHLCV names, whatever a `close="my_col"`-style kwarg points at (per-indicator dicts of a Custom Strategy included), and `df.ta.adjusted`. A wide caller-supplied DataFrame is trimmed the same way, so payload no longer scales with the frame at all.
* **A failing `df.ta` property reported itself as missing**: an `AttributeError` raised inside a property getter makes Python fall back to `__getattr__`, which answered `'AnalysisIndicators' object has no attribute '<name>'` — a false message, with the real error not even attached as `__context__`. Hit `df.ta.to_utc` and `df.ta.time_range` on a DataFrame without a `DatetimeIndex`, which now report `'RangeIndex' object has no attribute 'tz_localize'` and `'int' object has no attribute 'days'`. Unknown attribute names are unaffected.
* **`df.ta` property setters were silently ignored under pandas 3**: pandas 3 removed accessor caching, so `df.ta` returns a new `AnalysisIndicators` on every access and `df.ta.cores = 0`, `df.ta.adjusted = "adj_close"`, `df.ta.exchange = "LSE"`, and `df.ta.time_range = "months"` were discarded the moment they were assigned. This settable state now lives in `df.attrs` (as `_ta_chain` already did) and survives. `df.ta.last_run` likewise reports the actual last run instead of the accessor's construction time.

### Documentation
* **Quickstart troubleshooting: all-NaN results after resampling** (`docs/quickstart.md`): a NaN row *inside* the series — what `df.resample('D')` inserts for every weekend on a weekday-only feed — is a different failure from having too little data, and the existing entry pointed at the wrong diagnosis. 81 of 224 indicators return all-`NaN` on a 300-row daily frame with weekend gaps (`sma`, `stoch`, `macd`, `linreg`, `willr`, `stdev` among them) while `ema`, `rma` and `atr` still produce values, because a `rolling(length)` window needs `length` consecutive non-NaN bars and an `ewm` recursion does not. The docs list is kept in sync by `test_non_causal_indicator_is_documented`, which fails when an indicator marked non-causal in the test suite is missing from the page.

## Pre-0.3.78 — Historical

> Items below describe the state of the library as inherited from the original `pandas-ta` project and pre-2026 development. Preserved for historical reference.

### General
* A __Strategy__ Class to help name and group your favorite indicators.
* If a **TA Lib** is already installed, Pandas TA will run TA Lib's version. (**BETA**)
* Some indicators have had their ```mamode``` _kwarg_ updated with more _moving average_ choices with the **Moving Average Utility** function ```ta.ma()```. For simplicity, all _choices_ are single source _moving averages_. This is primarily an internal utility used by indicators that have a ```mamode``` _kwarg_. This includes indicators: _accbands_, _amat_, _aobv_, _atr_, _bbands_, _bias_, _efi_, _hilo_, _kc_, _natr_, _qqe_, _rvi_, and _thermo_; the default ```mamode``` parameters have not changed. However, ```ta.ma()``` can be used by the user as well if needed. For more information: ```help(ta.ma)```
    * **Moving Average Choices**: dema, ema, fwma, hma, linreg, midpoint, pwma, rma, sinwma, sma, swma, t3, tema, trima, vidya, wma, zlma.
* An _experimental_ and independent __Watchlist__ Class located in the [Examples](https://github.com/xgboosted/pandas-ta-classic/tree/main/examples/watchlist.py) Directory that can be used in conjunction with the new __Strategy__ Class.
* _Linear Regression_ (**linear_regression**) is a new utility method for Simple Linear Regression using _Numpy_ or _Scikit Learn_'s implementation.
* Added utility/convience function, ```to_utc```, to convert the DataFrame index to UTC. See: ```help(ta.to_utc)``` **Now** as a Pandas TA DataFrame Property to easily convert the DataFrame index to UTC.

### Breaking / Depreciated Indicators
* _Trend Return_ (**trend_return**) has been removed and replaced with **tsignals**. When given a trend Series like ```close > sma(close, 50)``` it returns the Trend, Trade Entries and Trade Exits of that trend to make it compatible with [**vectorbt**](https://github.com/polakowo/vectorbt) by setting ```asbool=True``` to get boolean Trade Entries and Exits. See ```help(ta.tsignals)```

### New Indicators
* _Arnaud Legoux Moving Average_ (**alma**) uses the curve of the Normal (Gauss) distribution to allow regulating the smoothness and high sensitivity of the indicator. See: ```help(ta.alma)```
* _Draw Down_ (**drawdown**) calculates the percentage decline from the peak equity of a trading account, or fund. See ```help(ta.drawdown)```
* _Candle Patterns_ (**cdl_pattern**) If TA Lib is installed, then all those Candle Patterns are available. See the list and examples above on how to call the patterns. See ```help(ta.cdl_pattern)```
* _Candle Z Score_ (**cdl_z**) normalizes OHLC Candles with a rolling Z Score. See ```help(ta.cdl_z)```
* _Correlation Trend Indicator_ (**cti**) is an oscillator created by John Ehler in 2020. See ```help(ta.cti)```
* _Cross Signals_ (**xsignals**) was created by Kevin Johnson. It is a wrapper of Trade Signals that returns Trends, Trades, Entries and Exits. Cross Signals are commonly used for **bbands**, **rsi**, **zscore** crossing some value either above or below two values at different times. See ```help(ta.xsignals)```
* _Directional Movement_ (**dm**) developed by J. Welles Wilder in 1978 attempts to determine which direction the price of an asset is moving. See ```help(ta.dm)```
* _Even Better Sinewave_ (**ebsw**) measures market cycles and uses a low pass filter to remove noise. See: ```help(ta.ebsw)```
* _Jurik Moving Average_ (**jma**) attempts to eliminate noise to see the "true" underlying activity.. See: ```help(ta.jma)```
* _Klinger Volume Oscillator_ (**kvo**) was developed by Stephen J. Klinger. It is designed to predict price reversals in a market by comparing volume to price.. See ```help(ta.kvo)```
* _Schaff Trend Cycle_ (**stc**) is an evolution of the popular MACD incorportating two cascaded stochastic calculations with additional smoothing. See ```help(ta.stc)```
* _Squeeze Pro_ (**squeeze_pro**) is an extended version of "TTM Squeeze" from John Carter. See ```help(ta.squeeze_pro)```
* _Tom DeMark's Sequential_ (**td_seq**) attempts to identify a price point where an uptrend or a downtrend exhausts itself and reverses. Currently exlcuded from ```df.ta.strategy()``` for performance reasons. See ```help(ta.td_seq)```
* _Think or Swim Standard Deviation All_ (**tos_stdevall**) indicator which
returns the standard deviation of data for the entire plot or for the interval
of the last bars defined by the length parameter. See ```help(ta.tos_stdevall)```
* _Vertical Horizontal Filter_ (**vhf**) was created by Adam White to identify trending and ranging markets.. See ```help(ta.vhf)```

### Updated Indicators

* _Acceleration Bands_ (**accbands**) Argument ```mamode``` renamed to ```mode```. See ```help(ta.accbands)```.
* _ADX_ (**adx**): Added ```mamode``` with default "**RMA**" and with the same ```mamode``` options as TradingView. New argument ```lensig``` so it behaves like TradingView's builtin ADX indicator. See ```help(ta.adx)```.
* _Archer Moving Averages Trends_ (**amat**): Added ```drift``` argument and more descriptive column names.
* _Average True Range_ (**atr**): The default ```mamode``` is now "**RMA**" and with the same ```mamode``` options as TradingView. See ```help(ta.atr)```.
* _Bollinger Bands_ (**bbands**): New argument ```ddoff``` to control the Degrees of Freedom. Also included BB Percent (BBP) as the final column. Default is 0. See ```help(ta.bbands)```.
* _Choppiness Index_ (**chop**): New argument ```ln``` to use Natural Logarithm (True) instead of the Standard Logarithm (False). Default is False.  See ```help(ta.chop)```.
* _Chande Kroll Stop_ (**cksp**): Added ```tvmode``` with default ```True```. When ```tvmode=False```, **cksp** implements "The New Technical Trader" with default values. See ```help(ta.cksp)```.
* _Chande Momentum Oscillator_ (**cmo**): New argument ```talib``` will use TA Lib's version and if TA Lib is installed. Default is True. See ```help(ta.cmo)```.
* _Decreasing_ (**decreasing**): New argument ```strict``` checks if the series is continuously decreasing over period ```length``` with a faster calculation. Default: ```False```. The ```percent``` argument has also been added with default None. See ```help(ta.decreasing)```.
* _Increasing_ (**increasing**): New argument ```strict``` checks if the series is continuously increasing over period ```length``` with a faster calculation. Default: ```False```. The ```percent``` argument has also been added with default None. See ```help(ta.increasing)```.
* _Klinger Volume Oscillator_ (**kvo**): Implements TradingView's Klinger Volume Oscillator version. See ```help(ta.kvo)```.
* _Linear Regression_ (**linreg**): Checks **numpy**'s version to determine whether to utilize the ```as_strided``` method or the newer ```sliding_window_view``` method. This should resolve Issues with Google Colab and it's delayed dependency updates as well as TensorFlow's dependencies as discussed in Issues [#285](https://github.com/twopirllc/pandas-ta/issues/285) and [#329](https://github.com/twopirllc/pandas-ta/issues/329).
* _Moving Average Convergence Divergence_ (**macd**): New argument ```asmode``` enables AS version of MACD. Default is False.  See ```help(ta.macd)```.
* _Parabolic Stop and Reverse_ (**psar**): Bug fix and adjustment to match TradingView's ```sar```. New argument ```af0``` to initialize the Acceleration Factor. See ```help(ta.psar)```.
* _Percentage Price Oscillator_ (**ppo**): Included new argument ```mamode``` as an option. Default is **sma** to match TA Lib. See ```help(ta.ppo)```.
* _True Strength Index_ (**tsi**): Added ```signal``` with default ```13``` and Signal MA Mode ```mamode``` with default **ema** as arguments. See ```help(ta.tsi)```.
* _Volume Profile_ (**vp**): Calculation improvements. See [Pull Request #320](https://github.com/twopirllc/pandas-ta/pull/320) See ```help(ta.vp)```.
* _Volume Weighted Moving Average_ (**vwma**): Fixed bug in DataFrame Extension call. See ```help(ta.vwma)```.
* _Volume Weighted Average Price_ (**vwap**): Added a new parameter called ```anchor```. Default: "D" for "Daily". See [Timeseries Offset Aliases](https://pandas.pydata.org/pandas-docs/stable/user_guide/timeseries.html#timeseries-offset-aliases) for additional options. **Requires** the DataFrame index to be a DatetimeIndex. See ```help(ta.vwap)```.
* _Volume Weighted Moving Average_ (**vwma**): Fixed bug in DataFrame Extension call. See ```help(ta.vwma)```.
* _Z Score_ (**zscore**): Changed return column name from ```Z_length``` to ```ZS_length```. See ```help(ta.zscore)```.
