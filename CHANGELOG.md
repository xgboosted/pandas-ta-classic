# Changelog

## [0.9.0] - 2026-10-21

### Changed
* **Signature defaults are `None` everywhere**: `bbands(ddof=0)`, `cdl_doji(asint=True)`, `cdl_pattern(name="all")`, `cpr(method="classic", timeframe="daily", levels="standard", width_analysis=True, price_position=True, virgin_cpr=False)`, `dpo(centered=True)`, `ichimoku(include_chikou=True, append_span=False)` and `xsignals(above=True, long=True)` wrote their defaults into the signature, the only registered indicators that did. They now take `None`, which their existing validation call resolves to the same default, so passing `None` means "the default" for every parameter of every indicator; results are unchanged (all registered output hashes identically). `tests/test_parameter_validation.py` checks every registered signature.
* **BREAKING — passing a whole number to a parameter with an int default no longer adds `.0` to the column names** (values are unchanged): `_pos_float` and `_number` returned `float(val)`, so an indicator renamed its output when given its own default. `kc(scalar=2)` named its columns `KCLe_20_2.0` where `kc()` gives `KCLe_20_2`, and `chop(scalar=100)`, `eom(divisor=100000000)`, `thermo(long=2)` and `squeeze_pro(kc_scalar_wide=2, kc_scalar_narrow=1)` did the same. A whole number now keeps the type of an int default, so `2` and `2.0` both name the column as the default does. Names change only for explicit calls with a whole number where the default is an int: `smi(scalar=10)` is now `SMI_5_20_5_10` (was `SMI_5_20_5_10.0`), and `kc(scalar=3)` is `KCLe_20_3` (was `KCLe_20_3.0`). Default calls and fractional values (`kc(scalar=2.5)`) keep their names. `tests/test_parameter_validation.py` passes every numeric default explicitly, as an int and as a float, for every registered indicator (over 300 parameters) and checks the names. All registered output on `SPY_D` hashes identically, with numba and with `NUMBA_DISABLE_JIT=1`.
* **License metadata is an SPDX expression**: `pyproject.toml` declares `license = "MIT"` (PEP 639) instead of the `{text = "MIT"}` table, which setuptools deprecates with a deadline of 2027-02-18; every build printed that warning. The wheel's metadata now carries `License-Expression: MIT` and `License-File: LICENSE`. The build requirement rises to `setuptools>=77.0`, the first release that accepts the expression (76.1 rejects it with a configuration error).
* **ruff 0.17, and one place for the black and ruff versions**: ruff 0.17.0 failed `code-quality` through `tools/check_lint_versions.py`, which required the pre-commit hook `rev` to match the ruff series CI installs; the test jobs, which need `code-quality`, were skipped meanwhile. The `pyproject.toml` floor is now `ruff>=0.17.0`, and the black and ruff pre-commit hooks are `repo: local` hooks with `language: system`, like `gen-core-stub` and `mypy-typecheck`, so they run the tools installed in the virtualenv and `pyproject.toml` is the only version source. The checker, its `make lint` call and its CI step are removed; a new ruff release now reaches CI as ordinary `ruff check .` findings. `pip install -U ruff black` brings a local checkout to the same rules.
* **BREAKING — `er`'s default signal thresholds are 0.8/0.2, not 80/20**: ER is a ratio in [0, 1], so the generic 80/20 default shared with `rsi`/`rsx` put `ER_10_A_80` at a constant 0 and `ER_10_B_20` at a constant 1 after warm-up. `attach_signals` takes per-indicator `xa`/`xb` defaults now, and `er` uses 0.8/0.2, so its columns read `ER_10_A_0_8` and `ER_10_B_0_2`. `rsi` and `rsx` keep 80/20.
* **Lint: ruff now flags confusable characters (`RUF001`–`RUF003`) and bidi controls (`PLE2502`)**: ten ambiguous characters in docstrings and comments (EN DASH, MINUS SIGN, a GREEK SIGMA) are replaced with their ASCII meaning. `tests/test_no_invisible_characters.py` keeps its hand-written scan for the non-Python files these rules do not cover, and its docstring names the multiplication sign instead of writing it.
* **`df.ta.strategy()` runs serially by default and no longer loses chained columns**: `df.ta.cores` defaulted to `cpu_count()`, so every call started that many spawn processes. Each one commits about 750 MB for OpenBLAS thread buffers, so `strategy("all")` on a million rows with 32 cores drove system commit to 87%; past 90% Windows throttles its WMI arbitrator and `import pandas` blocks indefinitely in a child. The pool also cost more than it saved below roughly 100,000 rows: measured on 32 logical cores, `strategy("all")` took 2.99 s at the old default against 0.19 s serially on 1,000 rows, and 3.04 s against 0.41 s on 10,000, because a spawn pool alone needs 0.5–1.7 s to start. `df.ta.cores` now defaults to `0`. Multiprocessing is opt-in per frame (`df.ta.cores = 8`) or per call (`strategy(cores=8)`, `strategy(executor=pool)`), and `None` resets `cores` to 0 rather than `cpu_count()`.

  The same rewrite fixes a silent correctness bug. Results were handed to a `Pool` in chunks, and a worker saw an earlier indicator's column only when both landed in the same chunk: `[{"kind": "sma", "length": 10}, {"kind": "ema", "close": "SMA_10"}]` produced both columns at `cores=0` and only `SMA_10` at `cores=2`, with no error, because the "column not found" warning was logged inside the worker and the `None` result was then discarded. Prepending one more indicator moved the chunk boundary and lost the chained columns at `cores=4` and `cores=8` too. `strategy()` now resolves its entries into a plan and splits that into ordered stages — an entry reading a column the frame does not have yet starts a new stage — so every mode gives the same columns, in the same order, with the same values, whether it runs serially or on workers. `tests/test_strategy_execution.py` asserts that for `"all"`, a category and a chained custom Strategy with and without a leading indicator; `test_custom_a` now also checks the chained `EMA_5_CLR` it silently lost.
* **BREAKING — `strategy(cores=...)` is read instead of ignored, and invalid values raise**: only `df.ta.cores` was ever consulted, so `df.ta.strategy("all", cores=0)` still started `cpu_count()` processes. The keyword now selects the worker count for that call and goes through `_pos_int`, so `-1`, `1.5`, `True` and `"2"` raise `ValueError: strategy() cores must be an integer >= 0, got ...` instead of being silently replaced. It is also capped at `cpu_count()`, like the `df.ta.cores` setter: one knob reached through two doors had two limits, so `df.ta.cores = 10000` gave 32 on a 32-core machine while `strategy(cores=10000)` would have opened 10,000 processes.
* **BREAKING — running on workers no longer changes how `strategy()` fails.** Four ways the parallel path diverged from the serial one. (1) A worker's exception was wrapped, so `except ValueError` around `df.ta.strategy(...)` stopped working as soon as the caller passed `cores=` or `executor=`; the original is re-raised, and both paths now give `ValueError: sma() length must be an integer > 0, got 0`. The traceback still does not survive pickling, so on Python 3.11+ a PEP 678 note names the indicator; below that the message carries it, which holds for 220 of the 221 indicators that raise for an invalid argument (the exception, `cdl_pattern`, names the pattern instead), but not for an error raised from numpy or pandas internals. (2) A dead worker surfaced as `BrokenProcessPool: ... terminated abruptly`, because the unguarded-`__main__` guard raises in the *child*, whose stderr is gone in a notebook; it is caught and re-raised naming that guard and an externally killed worker (out of memory, segfault), without claiming which. (3) That guard was armed only when `strategy()` opened the pool, so an unguarded script passing its own `executor=` recursed with no hint, and its `finally` disarmed concurrent calls in the same process; it is shared by both paths and refcounted. (4) The "returned no result" warning pointed at `core.py`, one frame short of the caller's line.
* **BREAKING — `df.ta.strategy()` raises on an argument it cannot use**: an unknown string logged `Not an available strategy.` through the package `NullHandler`, added no columns and returned `None`, so the documented `df.ta.strategy("CommonStrategy")` had never worked — a `Strategy`'s name was never matched, only `"all"` and category names were. It now raises `ValueError` listing the categories and pointing at `df.ta.strategy(ta.CommonStrategy)`, and a non-string, non-`Strategy` argument raises `TypeError`. `README.md`, `docs/quickstart.md` and `docs/tutorials.md` are corrected.
* **`strategy()` inside a worker process runs serially instead of failing**: nesting it in a `multiprocessing.Pool` raised `AssertionError: daemonic processes are not allowed to have children`. It now ignores `cores`/`executor` there. Starting workers from an unguarded script, which spawn re-imports, raises a `RuntimeError` naming `if __name__ == "__main__":` instead of forking until the machine stalls.
* **BREAKING — four more `strategy()` arguments that did nothing now raise**, found by auditing the Strategy system the way the worker path was audited. (1) `col_names` with fewer names than the indicator has columns logged through the `NullHandler` and returned, so `{"kind": "bbands", "length": 20, "col_names": ("BBL",)}` added *no* column instead of three; any count that does not match now raises `ValueError` naming both counts. (2) `exclude` was never type-checked, and a string extended the exclusion list character by character, so `strategy("momentum", exclude="rsi")` excluded `'r'`, `'s'` and `'i'` — nothing; a non-list, or a list holding a non-string, raises `TypeError`, and an unknown indicator name raises `ValueError`. (3) `exclude` was popped and dropped for a custom Strategy, where it silently had no effect; it raises `ValueError` pointing at the Strategy's own `ta` list. (4) A `Strategy` entry was only checked when it ran, and then by whatever failed first — `KeyError: 'kind'` for a missing kind, `TypeError: 'str' object is not a mapping` for a plain string — neither naming the entry. `Strategy(...)` now checks each entry's shape where it was written, and an unknown indicator name raises `ValueError: Strategy 'S' entry 1: 'not_an_indicator' is not an indicator` instead of a bare `AttributeError`. Existence is still checked at run time, because custom indicators may be loaded after the `Strategy` is built.
* **`strategy()` reports indicators that added no column**: an indicator that returned nothing made the run quietly produce fewer columns than entries. It now emits a `UserWarning` naming the indicator; a missing input column raises `KeyError` instead (see Fixed). `beta` and `correl` are left out of `"all"` and category runs unless a `benchmark=` is passed, so `df.ta.strategy("all", benchmark=other)` still computes them, and `ma` unless a `name=` is passed, since without one it would publish a second `EMA_10` beside the run's own `ema`.
* **BREAKING — no made-up `0.0.0` version for source builds without git metadata**: `pyproject.toml` no longer sets `fallback_version = "0.0.0"`. GitHub source archives (`pip install https://github.com/xgboosted/pandas-ta-classic/archive/main.zip`, Download ZIP) now carry the real version through `.git_archival.txt`, which `git archive` fills in (`export-subst` in `.gitattributes`). A source copy with neither `.git` nor that file, such as a Docker `COPY` of a checkout without `.git`, now fails at build time with setuptools-scm's `LookupError` instead of installing as `0.0.0`; include `.git`, or set `SETUPTOOLS_SCM_PRETEND_VERSION`. PyPI wheels and sdists are unchanged.
* **CI runs the test suite with numba installed**: a new `testing-numba` job runs the core tests with the `performance` extra on the second-newest supported Python, so the `@njit` path users of that extra run is tested; `tests/test_numba_parity.py` compares it with `NUMBA_DISABLE_JIT=1` for every indicator and candle pattern.
* **BREAKING — input shorter than an indicator's window returns an all-NaN result instead of `None`** (issue #145, case B): `ta.sma(close, length=50)` on 10 rows returned `None`, so `df.ta.sma(length=50, append=True)` silently added no column and a strategy on a short frame produced fewer columns than on a long one. Indicators now behave like `close.rolling(50).mean()`: the result has the input's index, the usual name and columns (`SMA_50`; `MACD_12_26_9`, `MACDh_12_26_9`, `MACDs_12_26_9`) and only NaN values. This covers all 149 indicators that returned `None` on a 3-row frame; `vp` keeps its bin rows. Code that checks `if result is None` for short data should check `result.isna().all()` instead. Still `None`: a missing required input (`beta` without `benchmark`), `vp`/`tos_stdevall` with `lookahead=False`, and the deprecated `ichimoku(as_dataframe=False)` tuple, which stays `(None, None)`. Two calls that returned `None` for an invalid argument now raise `ValueError`: `tos_stdevall` with a non-positive entry in `stds`, and `squeeze_pro` when `kc_scalar_wide > kc_scalar_normal > kc_scalar_narrow` does not hold. Results on inputs long enough for the window are unchanged (all 496 output columns hash identically, with and without numba). `tests/test_short_input_contract.py` asserts the new contract for every indicator.
* **pre-commit runs the type check too** (raised in the #142 review): a `mypy-typecheck` hook runs `make typecheck`, the same two passes as CI's `code-quality` job, on push; `default_install_hook_types` makes `pre-commit install` set up both the commit and push hooks, and `default_stages` keeps black, ruff and the stub regeneration on commit. `adosc`, `amat`, `aobv`, `massi` and `tsi` now comment why they drop a strategy-wide `length` (rule 3 in `AGENTS.md`), and the last three use `kwargs.pop("length", None)` instead of a membership test.
* **BREAKING — invalid parameters raise `ValueError` instead of silently using the default**: argument guards across the package replaced bad input with defaults. Numeric: about 290 guards like `length = int(length) if length and length > 0 else 10` turned 0, negative, NaN, bool and fractional values into the default (`ta.sma(close, length=0)` returned `SMA_10`, `length=2.7` became 2); `scalar = float(scalar) if scalar else 100` turned `scalar=0` into 100; `get_drift` turned 0/negative/fractional drifts into 1 and `get_offset` turned non-integers into 0; `macdext`/`mavp` MA-type codes outside 0–8 became defaults. Flags and options: about 76 `bool(x) if isinstance(x, bool) else default` guards turned `talib=1` into False and `asint=0` into True; about 35 string options (`mamode`, `cpr` `method`/`timeframe`/`levels`, `decay` `mode`, `vwap` `anchor`) fell back on non-strings or unknown values, and `ma("emaa")` returned an EMA. All now go through `_pos_int` / `_pos_float` / `_number` / `_bool_param` / `_str_param` / `get_drift` / `get_offset`, which return the default only for `None` and otherwise raise, e.g. `ValueError: sma() length must be an integer > 0, got 0`. Bounds are unchanged (`ebsw` still needs `length > 38`); `stdev`, `rvi`, `hma` and `cdl_z` state their own `length > 1`. Now honoured instead of replaced: `scalar=0`, `ddof=0` (`cdl_z`, `tos_stdevall`) and negative `offset`. Bugs fixed by the same sweep: `slope(as_angle=False)` returned angles, and `decay(mode="exponential")` ran the linear decay. A `df.ta.strategy(..., length=10)` run raises if a selected indicator rejects the value; pass `exclude=[...]`. Results for valid values and defaults are unchanged (all 498 output columns hash identically).
* **BREAKING — `ichimoku()` returns a single DataFrame**: the tuple deprecation from 0.8.32 announced this switch for the next breaking release. `ta.ichimoku(h, l, c)` returns the visible-period DataFrame (add `append_span=True` for the projected span rows) instead of a `(visible, span)` tuple. The `as_dataframe` parameter is removed and passing it raises `TypeError`; code that unpacks `visible, span = ta.ichimoku(...)` must switch to the DataFrame. `df.ta.ichimoku()` is unchanged.
* **BREAKING — non-Series input now raises `TypeError`** (issue #145): a list, numpy array, DataFrame or scalar passed where an indicator expects a Series used to make `verify_series()` return `None`, which silently dropped the column or surfaced as an unrelated error frames later. 0.8.32 kept returning `None` and emitted a `FutureWarning`. The warning is now a `TypeError` naming the indicator and the type it received, e.g. `sma() expected a pandas Series but got ndarray`. Pass the Series itself (`df['close']`, not `df['close'].values`). `None` for an omitted optional argument is unchanged; a Series shorter than the indicator's window now yields an all-NaN result (see above).
* **Lint gate: ruff's default rule set plus `ICN`, repo-wide, and a blocking mypy check** (split from #142): CI and pre-commit now run `ruff check .` from `[tool.ruff.lint]` instead of the four-rule `--select E9,F63,F7,F82` subset, and CI runs `make typecheck`. The codebase was fixed to pass, without changing any computed value (all 498 indicator and candle-pattern output columns hash identically before and after, with and without numba): PEP 604 annotations (`int | None`), sorted imports, `np.` instead of `from numpy import ...`, `min`/`max` for clamp `if`s, `itertools.pairwise`, and small fixes in tests, tools and examples. `ruff>=0.16.0` in the `lint` extra and pre-commit; `mypy` joins the `lint` extra. Library code has three inline `# noqa` with reasons and no per-file ignores. `tools/gen_core_stub.py` no longer writes a placeholder stub when one signature fails, so a broken indicator now fails the stub check. The `core.pyi` pipeline is gen, `ruff check --fix`, black.
* **Import hygiene leftovers from #142**: numpy/pandas imports hoisted out of function bodies (`utils/_core.py`, `volume/adosc.py`, `trend/sarext.py`, and four test modules); `tests/__init__.py` no longer inserts the project root into `sys.path` (pytest's rootdir handling and the editable install cover it); `__import__("pathlib")` replaced with `from pathlib import Path` in two test modules; `numpy.testing as npt` replaced with `np.testing`; a commented-out numpy import and a stale `nplog` comment removed; stale `[tool.mypy]` comments and the `[integration]` extra description in `CONTRIBUTING.md` corrected; the 0.8.32 "Lint-clean repo" entry no longer claims `ruff check .` passed at that release.
* **`tools/check_lint_versions.py` also checks the installed tools** (raised in the #142 review): the `>=` lint floors let CI install a newer ruff than pre-commit's exact `rev` while the check stayed green (CI ran ruff 0.16.7 against pre-commit 0.16.0). It now compares the installed ruff and black with the pre-commit `rev` by release series (ruff `0.MINOR`, black's year) and fails with instructions to bump both files. Patch releases within a series still pass.
* **Lint config**: `[tool.ruff.lint.isort] combine-as-imports = true`, so `from x import a, b as c` is one statement (`_meta.py`, `utils/__init__.py`, `utils/_math.py`, `tests/test_property_based.py`). `zero()` returns `float` and `is_percent()` is `TypeGuard[float]`, matching their `float` parameters. `AGENTS.md` gains the import conventions, a grep checklist, and notes on `--select`, pre-commit parity and the `core.pyi` pipeline (ported from #142, with its incorrect `banned-from` description fixed).
* **`make typecheck` now also checks `core.py`**: `core.pyi` shadowed it, so mypy never read the accessor and strategy engine (raised in the #142 review). A second pass checks the file directly. `Strategy.ta` is annotated `list | None` to match `AllStrategy`.
* **#142 pattern gaps closed**: `tools/gen_core_stub.py` writes PEP 604 annotations (`X | None`) and sorted imports itself, so its output matches the committed `core.pyi` before `ruff --fix` runs (identical on Python 3.12 and 3.14); the `cdl_pattern` and `ichimoku` docstrings drop `Union[...]`/`Tuple[...]`; `examples/ni.py` imports numpy/pandas at module scope; the `AGENTS.md` convention greps for function-body and commented-out imports now also scan `tests/`, `tools/`, `examples/` and `docs/`.
* **BREAKING — `calmar_ratio`, `max_drawdown` and `linear_regression` returned a sentinel for invalid input** (they now raise `ValueError`): `calmar_ratio(years=0)` returned `np.nan` for a non-positive window, `max_drawdown` returned the dollar drawdown for any unknown `method` string, and `linear_regression` returned `{}` when `x` and `y` had unequal lengths (the caller then failed with a `KeyError` several frames later). `years` now goes through `_pos_int`, `method` through `_str_param` with the `dollar`/`percent`/`log` choices, and `linear_regression` raises naming the two lengths. Results for valid inputs are unchanged.
* **One helper smooths over the valid rows**: `stoch`, `stochf`, `kvo` and `macd(asmode=True)` each sliced a series from its first valid row, smoothed it and put the shorter result back onto the input index by hand; a copy that forgot the last step left the missing rows `NaN` after `fillna`. `utils._core._on_valid_rows` now does all three steps. Output is unchanged: the raw output of every registered indicator and all 62 candle patterns, plus the option paths of the four (`mamode`, `asmode`, `fillna`, `fill_method`, `offset`, leading-`NaN` and all-`NaN` input), hashes identically before and after, with numba and with `NUMBA_DISABLE_JIT=1`.
* **`py.typed` means mypy now checks the package's own types**: before the marker a consumer's mypy treated the package as `Any` and reported nothing; with it, projects that run mypy on code importing `pandas_ta_classic` can see new errors after upgrading. The category subpackages re-export their indicators statically (under `if TYPE_CHECKING:`) and `core.pyi` declares `Strategy`, `AllStrategy` and `CommonStrategy`, so valid calls such as `from pandas_ta_classic.overlap import sma; sma(close, 10)` type-check. Note that `df.ta.*` stays `Any` under pandas-stubs, so accessor calls are not checked.
* **Candle patterns share one rolling-average helper** (the refactor itself changed no result): each of the 56 patterns that compares a candle against TA-Lib's average body or shadow range carried its own copy of the `TA_CANDLEAVERAGE` bookkeeping — a seed sum, a trailing index and an update line per setting and lag, handed to the `@njit` kernel as up to 32 positional arguments. `candle_average(ca, setting, lag, start_idx)` in `candles/_cdl_math.py` now returns those thresholds as an array, and the kernels read `threshold[i]`; a `start_idx` that would read before the first candle raises `ValueError`. The candle package shrinks from 6,269 to 4,062 lines of code (blank lines, comments and docstrings not counted). The refactor was bit-identical: all 62 patterns hashed the same before and after on 12 data sets, at TA-Lib's default settings and under 6 randomised settings tables (a distinct period and factor per setting, each period kept zero or non-zero as in the defaults, so a pattern reading the wrong setting or lag would show), with numba and with `NUMBA_DISABLE_JIT=1`. The helper now also uses TA-Lib's arithmetic for the average itself (see Fixed). The thresholds are arrays now instead of loop variables, so `cdl_pattern("all")` is about 3% slower on 10,000 bars and 10% slower on 200,000.
* **BREAKING — float32 input computes in float64** (results change only for float32 or float16 input): `verify_series()` passed a numpy float32 Series through, so 54 indicators returned float32, 4 more (`aobv`, `ha`, `ichimoku`, `thermo`) mixed float32 and float64 columns, and the values lost digits computing in float32 (155 columns differed from the same values given as float64). A float32 or float16 Series is now converted to float64, as nullable and pyarrow input already is, so the result equals the float64 one, dtype included (`tests/test_nullable_input_contract.py`). numpy integer input is unchanged: it was decided to stay as numpy computes it. float64 input is untouched; every registered output on `SPY_D` hashes identically.

### Added
* **Price-level contract** (`tests/test_shift_contract.py`): negative prices are real data (WTI settled at -37.63 USD on 2020-04-20, day-ahead power trades below zero, back-adjusted futures and spreads cross zero), and an indicator built from differences, sums, extremes and ranges cannot tell them from the same series moved up. Every registered indicator is run with open, high, low and close moved by +1000, by minus the median close (crossing zero) and below zero altogether, one test per shift; each column must come back unchanged or moved by the same amount, without a `RuntimeWarning`. 162 indicators pass as they are; a Hypothesis property adds random paths and shifts for 15 of them. Exempt with the reason: 31 indicators that are relative to the price by definition (`roc` and the indicators built on it, `ppo`, `natr`, `bias`, `mfi`, `log_return`, `hvol`, `mcgd`, ...; strict xfails, `TALIB:` for `sarext` and `ht_trendmode`, whose level dependence is TA-Lib's rule), seven percent columns inside otherwise additive indicators (`BBB`, `ACCBL`/`ACCBU`, `CPR_WIDTH_PCT`/`CPR_WIDTH_CLASS`, `DD_PCT`/`DD_LOG`), and the warm-up of seven recursive filters whose state starts at `0.0` (`ebsw`, `mama`, the Hilbert-transform family). Not settled and not pinned: what a level-dependent indicator should do at a price at or below zero. Today `mcgd` and `drawdown`'s `DD_LOG` turn NaN without a warning, `log_return`, `hvol`, `avolume` and `vfi` raise only numpy's `RuntimeWarning`, and `sarext`'s `-SAR` encoding of a short position cannot represent a negative SAR.
* **TA-Lib oracle over the data problems met so far** (`tests/test_oracle_registry.py`): one table compares the 92 indicators and 61 candle patterns that have a TA-Lib counterpart with it, values and NaN mask, on `SPY_D` and on flat, flat-block, no-range, planted flat/bodiless, malformed and zero-volume frames, on prices scaled by `1e-6` and `1e6`, on a flash spike and crash, and on volume of `1e15`. It uses `assert_talib`'s tolerance element by element, with the absolute term scaled down for columns smaller than 1, so a `1e-6` relative error is caught at every price scale. A completeness check fails when an indicator listed with a TA-Lib counterpart in `docs/indicator_support_matrix.rst` has no case; it found the counterparts of `linreg`, `true_range`, `uo` and `wcp` missing from that page. Known differences are strict xfails with the reason, and are mostly TA-Lib's own, partly depending on its version (measured with 0.7.1 and 0.8.2): the Hilbert-transform family amplifies rounding on constant input; before 0.8, `CCI` reads `±66.67` on a constant window from a `1.1e-13` running-sum residue and `CORREL` reads `0.0` at small prices; from 0.8, `WILLR` is clamped to `-100..0`, so it reads `0.0` where malformed bars put the close above the window's highest high; native computes the formula as 0.7 did, which falls outside that range and shows the bad bars. `STDDEV` and `VAR` lose digits to their running sums of squares (`3e-8` relative on one frame, where native is exact), so these two compare at `1e-7` instead.
* **Registry-wide contracts for missing bars, price scale, zero volume and integer input**: every registered indicator now also runs against a missing whole bar, a five-bar outage, a bar missing only its volume or only its range, a missing newest bar and a gappy calendar (`tests/test_data_gaps_contract.py`); prices scaled by `1e-6` and `1e6`, where each column must stay unchanged or scale by `k` or `k**2` (`tests/test_scale_contract.py`); a zero-volume frame (`tests/test_degenerate_input.py`); and prices in ticks as `int64` and `Int64` (`tests/test_nullable_input_contract.py`). What they found is pinned as strict xfails with the reason, not changed here: `fisher` and `msw` bind an absolute `0.001` at small prices, kept for parity with TradingView's `ta.fisher` and Tulip's `msw`; `emv` and `marketfi` read `inf` and `eom` NaN over a bar that moved on zero volume, and `cmf`, `vosc`, `vwma`, `vwap` and `vwmacd` read NaN over a window without volume, as documented under "Zero Volume" in `docs/indicators.rst`.
* **Invisible-character guard** (`tests/test_no_invisible_characters.py`): every tracked text file is rejected if it holds a character that cannot be seen or is indistinguishable from an ASCII one — the no-break spaces, the zero-width family, `U+2011` (looks like `-`), the bidi controls behind Trojan Source (CVE-2021-42574) and a UTF-8 BOM. Both spellings count: the character in the file's bytes, and, in a Python source, a `\uXXXX`/`\xXX` escape that the interpreter turns back into it. Ordinary non-ASCII text is deliberately allowed: the em dashes here, the macrons in "Ichimoku Kinkō Hyō", `©` in a citation and `×` in a benchmark table all say what they mean, and Python 3 source is UTF-8 by default (PEP 3120). The forbidden set is built from code points at run time, so the module does not flag itself.
* **`df.ta.strategy(executor=...)`**: pass any `concurrent.futures.Executor` and `strategy()` runs on it instead of opening a pool of its own, so worker start-up — about 0.66 s each, most of it loading the numba cache — is paid once rather than per call. Within a stage the tasks are split round robin into one group per worker and only the columns that stage can reach are sent, so the DataFrame is pickled once per group rather than once per indicator. Roughly 3x faster than serial at 100,000 rows and at a million, and slower below about 100,000, where starting workers costs more than the indicators do. `docs/strategies.rst` covers when this pays, the `if __name__ == "__main__":` guard that spawn requires, and why `OPENBLAS_NUM_THREADS=1` must be set before numpy is imported rather than in the pool's `initializer=`.
* **API consistency map** (`tests/test_api_consistency.py`): registry-wide questions about the public API (output dtype, flag encodings, float32 and all-NaN input, index handling, column names, defaults, docstrings, accessor vs function, parameter names, name collisions), each compared with a table of the indicators that answer differently from the majority. Every table and row carries a status, `OPEN:` for a defect or an undecided question, `KEPT:` for a decided exception; a new deviation fails until it is added, a fixed one until its row is removed. Every row it found is decided: fixed in this release (float32 input, flags before they can know, `CDL_INSIDE`'s scale, the math docstrings, signature defaults, explicit-default renames, duplicate index labels, `result.category`, all-NaN input) or recorded as `KEPT:` with its reason (pandas-ta's column and parameter names, the accessor's classic `ad`/`adosc`/`cmf`/`psl`, percent vs fraction, `ma`/`vp` without `offset`). The tables the fixes emptied stay as `OPEN:` guards.
* **Warm-up contract sweep** (`tests/test_warmup_contract.py`): two properties over every registered indicator and every column it returns. (1) No column may hold a value in front of its own warm-up — the signature is a short finite run at the very front, followed by the real NaN warm-up run, holding a value outside the range the column takes once it is settled, which is what an `np.zeros`/`np.ones` array hands back. Genuinely one-sided columns (`PSARl`/`PSARs`, `SUPERTl`/`SUPERTs`, `HILOl`/`HILOs`, `QQEl`/`QQEs`) start with a short run too, but inside their settled range, so they pass without an exception list. (2) A column whose values are all in {-1, 0, 1} describes a bar, so it must be NaN wherever every continuous column of the same result is NaN. The sweep found the `supertrend`, `qqe` and `thermo` defects below; `CPR_POSITION` and `CPR_WIDTH_CLASS` were exceptions as `int8` until they became float64 (see the flags entry under Fixed).
* **`fill_method` contract sweep** (`tests/test_index_contract.py`): every registered indicator is called with `fill_method="ffill"` and `"bfill"`, and each column must be filled as far as its own values reach — no `NaN` from its first value on with `ffill`, none up to its last value with `bfill`. The `fillna` sweep only checked `fillna=0`; run against the code before the `fillna` fix above, this sweep fails on the same seven indicators (`md`, `linregangle`, `linregintercept`, `linregslope`, `stochf`, `kvo`, `aobv`) and passes on every indicator now.

* **BREAKING — `non_zero_range()`** (`ta.non_zero_range`, `ta.utils.non_zero_range`): it replaced an exact-zero difference with `sys.float_info.epsilon`, which degrades gracefully only where the numerator is zero too; everywhere else it left an epsilon in the output, or multiplied a quotient by `4.5e15`, or turned a degenerate window into an ordinary-looking value (the entries under Fixed list each case). The last eleven modules that called it now take the exact difference: `cdl_doji`, `bop`, `fisher`, `kdj`, `stoch`, `stochf`, `stochrsi`, `kama`, `dx`, `ad` and `cmf`. Where the difference is a divisor, the divisor is masked at its own site, the same shape as `willr`: a window with no range reads `0.0`, TA-Lib's marker, and `kama`'s efficiency ratio reads `1.0`, TA-Lib's value. `stochrsi`, `dx` and `fisher` are unchanged on every frame measured — `SPY_D`, flat, flat-block, `high == low` with a moving close, malformed OHLC, flat bars and doji planted in `SPY_D`, and the same on int64 prices — with numba and with `NUMBA_DISABLE_JIT=1`; so are `stoch`, `stochf` and `kdj` everywhere but on the windows in the entry below. 0.9.0 ships no deprecation (rule 11 in `AGENTS.md`), so the name is gone at once; accessing it raises `AttributeError` with the replacement, `(num / den).mask(den == 0, 0.0)` over the exact `high - low` (`from pandas_ta_classic.utils import non_zero_range` raises Python's plain `ImportError`). `tests/test_degenerate_input.py` adds a Hypothesis property per way the epsilon reached the output, and a registry-wide sweep that no column carries an epsilon-scale value (`0 < |x| < 1e-12`) on the flat, flat-block and no-range frames.

Neither could run: all 62 names in `ALL_PATTERNS` have a native module, and `cdl_pattern()` rejects a name that is in neither list before dispatching. The branch, the `talib.abstract` import that fed it and the now-unused `Imports`, `apply_fill` and `apply_offset` imports are gone; the remaining `else` raises `RuntimeError` for the only way a name can still arrive there, `ALL_PATTERNS` drifting from the discovered modules. `tests/test_indicator_candle.py` now asserts the two lists match, so the drift fails loudly instead of reaching a fallback. `talib.abstract` was the only TA-Lib submodule the package imported, so the `[[tool.mypy.overrides]]` entry drops `"talib.*"`, which mypy had started reporting as an unused section.

They need an explicit check rather than simply disappearing, because `strategy()` forwards unknown keywords to the indicators — that is how `strategy(length=10)` works — so a removed keyword would otherwise pass through in silence.

* **BREAKING — `tsignals(trend_reset=...)` and `xsignals(trend_reset=...)`**: documented as "value used to identify if a trend has ended" but never read, so it never changed a result. It is removed without a deprecation step (AGENTS.md rule 11 exception), and passing it raises `TypeError`. `trade_offset` and `offset` are now keyword-only, so an old positional call cannot slide a value into `trade_offset`; it raises `TypeError` too.

The example notebooks no longer call the removed names. `pandas_ta_classic.utils.get_time` went too; see the next entry.
* **BREAKING — `df.ta.exchange` and `pandas_ta_classic.utils.get_time`; `df.ta.last_run` and `Strategy.created` are UTC `datetime`s**: `get_time` survived the removal above as the source of the `last_run` and `created` strings, and `df.ta.exchange` only picked whose clock those strings showed. Both were wrong. The exchange hour was the host's *local* hour plus a fixed offset from `EXCHANGE_TZ`, so it was right only on a UTC host: on a CEST host every exchange read wrong (NYSE 7:48 at a real 5:48). The fixed offsets ignored daylight saving, and some never matched (`BMF` -2, Brazil has been UTC-3 since 2019). The string also carried the locale's time zone name (`Mitteleuropäische Sommerzeit`), so it could not be parsed back reliably. `df.ta.last_run` and `Strategy.created` are now `datetime.now(timezone.utc)`, a stdlib `datetime` you can compare and convert (`df.ta.last_run.astimezone(ZoneInfo("America/New_York"))`). `EXCHANGE_TZ` is gone from `_meta`. Reading or setting `df.ta.exchange` raises `AttributeError` naming the replacement: without the raising setter, pandas 3 would put an assignment on a throwaway accessor and it would silently do nothing. It is `AttributeError` rather than the `TypeError` used for removed parameters, so `hasattr(df.ta, "exchange")` is `False` and `getattr(df.ta, "exchange", None)` returns the default. A frame saved by 0.8.x keeps the old display string in `df.attrs` until its next run overwrites it; `df.ta.last_run` raises `ValueError` naming the key until then, rather than `fromisoformat()`'s parse error.

Because every indicator takes `**kwargs`, an existing `drift=` call keeps running and the value still has no effect; it only stops warning. It is absorbed rather than rejected because `drift` is a strategy-wide argument: `df.ta.strategy("momentum", drift=2)` sets it for the 33 indicators that use it. Remove the argument from direct calls. `tsignals` always uses a 1-period difference.

Behaviour is unchanged: `ta.rolling_max(close, length=0)` raises `ValueError: rolling_max() length must be an integer > 0, got 0`.

The missing bar now reads NaN and each recursion carries its state across it. A chained recursion no longer receives the carried value as an input, so its values after the gap change until the gap has left it: within 2 bars for most, about 500 for `adx`, `qqe` and `trix` (on `SPY_D` with one missing bar; the largest differences are `stc` 95.7, `kdj` 42.4 and `qqe` 11.2 points). Every registered output on complete `SPY_D` hashes identically, with numba and with `NUMBA_DISABLE_JIT=1`.

All registered output on `SPY_D` hashes identically, with numba and with `NUMBA_DISABLE_JIT=1`.

The input is now cast to float64 before the loop, as `macd`'s is, so `vidya` computes on it.
* **BREAKING — `stochrsi` read noise on a flat run after real movement**: Wilder's averages decay by the same factor on every flat bar, so the RSI is constant in exact arithmetic but wobbles by about `1e-14`, and %K divided that wobble by itself — anything in `0..100` (measured 16.7, 66.7, 100). A window whose RSI range is below `degenerate_zero()`'s `1e-12` now has no range and reads `0.0`, the marker. RSI has a fixed 0–100 scale, so no real range is that small. TA-Lib 0.8's `STOCHRSI` reads `0.0` there as well; 0.7 still reads the noise (`test_oracle_registry.py` records the difference for it). `SPY_D` is unchanged.
* **BREAKING — `fisher` lost the rest of the series to one missing bar**: the recursion `v = 0.66 * pos + 0.67 * v` carried a NaN from `high` or `low` forward forever, because `fisher` skipped only a leading NaN run; on `SPY_D` with one missing high, all 4,740 later bars read NaN. It now skips every missing bar (`skip_leading_nan(..., interior=True)`), like the other recursive indicators: the result equals `fisher` on the same series with that bar removed, with NaN only at the bar itself. As for those indicators, `fillna=` no longer fills the missing bar, and `offset` and the signal line count the bars present. Data without gaps is unchanged, at every price scale.
* **Property tests failed at random on a cold checkout under `pytest -n auto`** (`tests/test_property_based.py`): Hypothesis's `too_slow` health check fails a test that draws fewer than about ten valid inputs in its first second of wall-clock time. With a fresh worktree (no `__pycache__`, no numba cache) the first property test in each xdist worker shares the CPU with the other workers compiling numba, and draws that take 1 ms warm took over 100 ms, so whichever property test ran first failed: `test_default_draws_finite_prices`, `test_verify_series_none_input_returns_none` or `test_metrics_reject_a_zero_span`, in 4 of 6 cold runs. The new `tests/conftest.py` suppresses `too_slow` in Hypothesis's default profile; the per-example `deadline` is unchanged. 21 tests listed `HealthCheck.function_scoped_fixture` in their own `@settings`, which replaces the profile's list rather than adding to it; they are `unittest.TestCase` methods that take no pytest fixture, so the entry had no effect and is gone. 10 cold runs in a row now pass.
* **`test_adxr_ext` passed only when run after `test_adx_ext`** (`tests/test_ext_indicator_trend.py`): the class shares one frame, and `adx` had already appended `DMP_14`/`DMN_14`, so `adxr(append=True)` overwrote them in place and the asserted column order `DMP_14, DMN_14, ADXR_14` held only in file order. Each of the other 321 extension tests passes on its own.
* **BREAKING — `linear_regression` returned a wrong slope for an x far from zero, and an infinite one for a nearly flat x** (results change for those inputs; `jensens_alpha` moves by about 1e-14 relative, `pure_profit_score` is bit-identical on SPY_D): the slope used the one-pass form `m * sum(x * y) - sum(x) * sum(y)`, which cancels catastrophically when x sits far from 0 with a small spread. With a 1e-3 spread the slope was 3.5% off at x ~ 1e4, 99% off at 1e6, and had the wrong sign at 1e8 (1e-2 spread); it now uses centred sums and agrees with `np.polyfit` to 1e-13. The `x.std() != 0` guard missed the float residue of a flat x (0.1 + 0.2 next to 0.3 gives a deviation of 4e-17), so the slope divided by it and read `inf`, next to a correlation made of rounding noise; it now uses a tolerance relative to x's own scale (an absolute one missed the same residue at 1e6, where one ULP leaves a deviation of ~8e-11 and the slope read -1.8e8) and returns `NaN` throughout. A flat y keeps its slope (0) and intercept (its level), and its undefined correlation is now `NaN` without `np.corrcoef`'s `RuntimeWarning: invalid value encountered in divide`, which `pure_profit_score` passed on to callers for a flat series. The function no longer changes numpy's global error state with `np.seterr`; a local `np.errstate` covers the t-statistic, and `drawdown`'s log column gets the same treatment (its values are unchanged). `tests/test_property_based.py` checks the slope against an exact rational least-squares fit for x at any level from 1e-12 to 1e9, and that an x of two adjacent floats has no fit.

* **BREAKING — `pdist` and `rvgi` carried the epsilon into their output**: `pdist` sums `2 * (high - low)`, `|open - close[-1]|` and `-|close - open|`, dividing by nothing, so a bar that covered no distance reported `2 * eps + eps - eps` instead of none. `rvgi` puts `close - open` over `high - low`, both smoothed; `high == low` forces `open == close` for a valid bar, so the numerator vanishes with the divisor and masking on the divisor alone is enough, as in `bbands`. ### Performance
* **`true_range`, `uo` and the directional-movement family compute in one vectorised pass** (results bit-identical): `true_range` takes the elementwise `np.fmax` of its three ranges instead of a `concat` and a row `max`, `uo` the NaN-propagating `np.maximum`/`np.minimum` instead of a three-column frame, and `dm`, `adx`, `dx`, `plus_dm`, `minus_dm` and the cross helpers clamp near-zero values with one `Series.mask` instead of `Series.apply(zero)` per element (casting float32 to float64 first, as `apply` did). Best of 7 on SPY_D (5,241 bars) / 100,000 bars: `true_range` 0.88 → 0.37 ms / 11.1 → 1.8 ms, `atr` 1.05 → 0.56 / 13.9 → 3.0, `uo` 2.0 → 1.4 / 20.2 → 9.7, `adx` 3.6 → 1.9 / 45.6 → 7.7, `dm` 1.9 → 0.7 / 32.0 → 4.1, `cross` 1.2 → 0.7 / 20.9 → 0.8. Every registered indicator (plus variants of the touched ones and `cdl_pattern("all")`) hashes identically before and after on SPY_D, SPY_D with NaN gaps and a frame with a flat stretch, with numba and with `NUMBA_DISABLE_JIT=1`, and in 2,310 edge cases (±0.0, ±epsilon, NaN and ±inf in each input, int64, float32 and nullable input, other index types).
* **`macd`, `vidya` and `adosc` run their recursions compiled with numba** (values identical): the EMA loop behind `macd`'s TA-Lib-seeded lines, `vidya`'s adaptive average and `adosc`'s two AD EMAs moved into `@njit` kernels. The SMA seeds stay numpy means (numba's `mean` sums in a different order), and the inputs are cast to float64 first, so object-dtype input still computes. `vidya` on `Decimal` input now computes (see Fixed). Best of 7 with numba on SPY_D (5,241 bars) / 100,000 bars: `macd` 3.6 → 0.27 ms / 66 → 2.6 ms, `vidya` 2.7 → 0.70 / 42 → 5.5, `adosc` 2.5 → 0.45 / 42 → 2.5. Without numba the loops run as before. Every registered indicator (plus variants of these three) hashes identically before and after on three frames, on Windows and on Linux, and 165 edge cases (float32, int64 and object input, NaN gaps, leading NaN, inf, ±0, negative and constant prices, lengths at the window boundary, `asmode`, `signal_indicators`, `drift`, `open_`) match value, dtype and index, with numba and with `NUMBA_DISABLE_JIT=1`. The one bit that can differ is the sign of a NaN: where `adosc`'s AD line is NaN on every bar (measured on prices around `1e-320` and on float16 input), the compiled loop returns some of those NaNs with the sign bit set on Windows (not on Linux); a NaN with either sign is NaN to every comparison and to `isna()`, and no value changes.
* **The six `ht_*` indicators are about 110x faster** (last-bit differences on Linux, see below): `cycles/_hilbert.py` `_hilbert_transform_loop` is a per-bar Python loop shared by `ht_dcperiod`, `ht_dcphase`, `ht_phasor`, `ht_sine`, `ht_trendline` and `ht_trendmode`, and it dominated every run that touched the cycles category — 72% of a serial `df.ta.strategy("all")`. It now carries `@njit(cache=True)`, like the 87 other hot loops in the package: 1.66 s to 0.015 s on 100,000 rows on Windows (1.27 s to 0.016 s on Linux), and `strategy("all")` serial 14.3 s to 3.7 s (11.3 s to 2.9 s). Every other indicator is untouched: all 224 indicator outputs and `cdl_pattern("all")` hash identically before and after on both platforms, with numba and with `NUMBA_DISABLE_JIT=1`, as do 98 Hilbert edge cases (interior NaN, leading NaN, +/-inf, +/-0.0, constant, empty, all-NaN, 1e308, 5e-324). Without numba installed, or with `NUMBA_DISABLE_JIT=1`, the decorator is the existing no-op and results are bit-identical to before on every platform.

  With numba active on Linux, `ht_dcperiod`, `ht_dcphase`, `ht_phasor` and `ht_sine` change in the last bits. numba compiles `np.arctan` to the platform `atan` (bit-identical to `math.atan`), while numpy uses its own implementation, and on glibc the two differ by one unit in the last place for 0.11% of inputs (214 of 200,000 samples, at most 2.2e-16 absolute); the `period` recursion then carries that forward. Measured on the bundled sample data with numpy 2.5.3 on both platforms: at most 7.8e-16 relative for `HT_DCPERIOD` and 4.9e-14 for `HT_SINE`, with no NaN moving; `ht_trendline` and `ht_trendmode` are unchanged, and so is every value on Windows, where numpy's `arctan`, `math.atan` and numba agree exactly. `np.sin`, `np.cos` and the phase lookup tables are bit-identical on both platforms, the difference is independent of numpy's AVX-512 dispatch, and the TA-Lib oracle comparisons pass unchanged.

### Changed
* **Short-window hardening in `rma`, `linreg` and `_sliding_weighted_ma`**: all three assumed the `verify_series` `min_length` guard had already rejected a window longer than the series — `rma` seeded at `close.iloc[length - 1]`, and the other two built a `sliding_window_view` wider than the input array. No route to any of them was found through the public API, so this changes no observable behaviour; it is defence in depth, prompted by the `ema` seeding bug (see Fixed), which was equally unreachable until a particular composition of indicators exposed it. `min_length` models a single window while real lookback is compositional, so it cannot rule out the next such case. All three now return an all-`NaN` Series when no full window fits, matching `statistics/variance.py` and `_sliding_argextreme`.
* **`td_seq` ~3500× faster (numba)**: the Tom DeMark Sequential consecutive-run count replaced `rolling(13).apply(python_callback)` with a numba `@njit` loop (`~1912 ms` → `~0.5 ms` per 5000-bar call, the single largest indicator bottleneck). Bit-for-bit identical; falls back to a plain Python loop without numba. Reproduce with `python tools/bench_indicators.py`.
* **`hilo` ~250× faster (numba)**: the Gann HiLo per-bar `.iloc[]` state loop moved into a numba `@njit` kernel over numpy arrays (`~130 ms` → `~0.5 ms` per 5000-bar call). Output is identical for all `mamode`s; falls back to a plain Python loop without numba.
* **`jma` ~130× faster (numba)**: the Jurik Moving Average per-bar recursion (volatility bands + 3-stage filter) moved into a numba `@njit` loop with scalar coefficients precomputed by the caller (`~50 ms` → `~0.4 ms` per 5000-bar call). The trailing-window average uses `np.mean` in place of the original `np.average`; for an unweighted call numpy computes these bit-for-bit identically, so the **numba-off fallback is bit-identical to the previous output**. Under numba (JIT on), `np.mean` compiles to numba's own reduction, whose summation order differs from numpy's at the ULP level (~4e-16 relative, full float64 precision); compounded through the recursive `jma[i] = jma[i-1] + det1` update the JIT path lands within ~1 ULP of the original but not bit-for-bit identical. Inconsequential for any practical use; `jma` is the only optimised indicator here whose JIT and numba-off paths are not bit-identical to each other (every other one is).
* **`ha` ~50× faster (numba)**: the recursive Heikin-Ashi open (`df.iat[]` scalar loop) moved into a numba `@njit` scan over the precomputed HA_close array (`~75 ms` → `~1.5 ms` per 5000-bar call). Output is identical; falls back to a plain Python loop without numba.
* **`stc` ~40× faster (numba)**: the two Schaff Trend Cycle stochastic-smoothing loops moved into a shared numba `@njit` kernel, parametrised by the gate series (pass 1 gates on the rolling minimum, pass 2 on the rolling range) (`~82 ms` → `~2 ms` per 5000-bar call). Output is bit-for-bit identical (the cumulative 8-decimal rounding is preserved inside the kernel); falls back to a plain Python loop without numba.
* **`wad` ~15× faster**: Williams A/D replaced `Series.combine(prev_close, max/min)` (a per-element Python callback) with vectorised `np.fmax`/`np.fmin` (`~16 ms` → `~1 ms` per 5000-bar call). Output is identical; pure numpy, no numba needed.
* **`wilder_smooth` / `dm` ~5× faster (numba)**: Wilder's cumulative smoothing (`utils/_wilder.py`, used by `dm`) moved its per-bar recursion into a numba `@njit` kernel. The seed (`np.nansum(raw[1:length])`) is still computed with numpy in the caller and passed in, so the cumulative sum matches bit-for-bit — the kernel runs only the deterministic scalar recursion. `dm` `~10.5 ms` → `~2.0 ms` per 5000-bar call. Bit-for-bit identical; falls back to a plain Python loop without numba.
* **`pmax` ~4.6× faster (numba)**: the PMAX adaptive-band / trend-direction per-bar loop is now `@njit`-compiled with its Python-list accumulators replaced by numpy arrays (`~5.4 ms` → `~1.2 ms` per 5000-bar call; the residual is the ATR/MA prep). The loop is pure comparisons + `min`/`max` + assignment, so output is bit-for-bit identical; falls back to a plain Python loop without numba.
* **`npround` ~400× faster (vectorised)**: replaced the per-element `close.apply(np.round)` Python callback with a single vectorised `np.round(close)` (`~6 ms` → `~0.02 ms` per 5000-bar call). Output is bit-for-bit identical.
* **`aroon`, `maxindex`, `minindex`, `minmaxindex` ~9–17× faster (vectorised)**: the rolling `argmax`/`argmin` arg-position loops (`Series.rolling(length).apply(np.argmax/argmin, raw=True)`) now use a shared `_sliding_argextreme()` helper built on `numpy.lib.stride_tricks.sliding_window_view` (mirrors the existing `_sliding_weighted_ma`). aroon `~12 ms` → `~0.7 ms`, minmaxindex `~8 ms` → `~0.8 ms`, maxindex/minindex `~4 ms` → `~0.4 ms` per 5000-bar call. Integer arg-positions → bit-for-bit identical output; pure numpy, no numba needed.
* **`ebsw` ~850× faster (numba)**: the Even Better SineWave per-bar `.iloc[]` HighPass + SuperSmoother recursion moved into a numba `@njit` kernel over a numpy array, with the (bar-invariant) filter coefficients hoisted out of the loop and the 2-element `FilterHist` list replaced by two scalars (`~34 ms` → `~0.04 ms` per 5000-bar call). Output is bit-for-bit identical; falls back to a plain Python loop without numba.
* **`kama` ~90× faster (numba)**: Kaufman's Adaptive MA per-bar smoothing recursion moved into a numba `@njit` loop over numpy arrays (the vectorised efficiency-ratio/smoothing-constant prep stays in pandas) (`~30 ms` → `~0.3 ms` per 5000-bar call). Output is bit-for-bit identical; falls back to a plain Python loop without numba.
* **`mama` ~55× faster (numba)**: the MESA Adaptive MA / FAMA inline Hilbert-Transform loop is now `@njit`-compiled (`~16 ms` → `~0.3 ms` per 5000-bar call). Output is bit-for-bit identical (verified against the pure-Python `.py_func`); falls back to a plain Python loop without numba.
* **Candlestick patterns ~32× faster (numba)**: all 60 native `cdl_*` pattern per-bar detection loops (the TA-Lib incremental running-window algorithm) moved into numba `@njit` kernels over numpy arrays, with the average-factor constants and range arrays hoisted by the caller. `cdl_pattern(name="all")` drops from `~288 ms` to `~9 ms` per 5000-bar call. Output is bit-for-bit identical for every pattern; falls back to a plain Python loop without numba.
* **Faster cold import (~3–4×)**: `import pandas_ta_classic` takes ~280 ms (was ~930 ms) because indicator functions load on demand. Attribute access is unchanged — `ta.sma`, `ta.rsi`, `ta.cdl_doji`, `ta.momentum` and friends all still resolve, now through the module's `__getattr__` (PEP 562) instead of eager binding. See the star-import entry below for the one case that did change.
* **BREAKING — `from pandas_ta_classic import *` no longer binds the indicator functions**: the eager `from pandas_ta_classic.<category> import *` chain in `core.py` used to leak every indicator into the top-level module dict, so a wildcard import bound ~427 names, `sma` and `rsi` among them. With on-demand loading they resolve through `__getattr__` and are therefore absent from `__all__`, so `from pandas_ta_classic import *; sma(df["close"])` now raises `NameError`. ### Deprecated
* **Passing a non-Series where an indicator expects a Series** (issue #145): a list, numpy array, DataFrame or scalar used to make `verify_series()` return `None` silently, so `ta.sma(df['close'].values)` returned `None` and `df.ta.sma(close=df['close'].values)` added nothing — the mistake surfaced, if at all, as an unrelated error several frames later (backtesting.py #342, #1243). It now emits a `FutureWarning` naming the indicator and the type received, attributed to the calling line, and still returns `None`; a future release will raise `TypeError`. A Series shorter than the indicator's window and an omitted optional argument (`None`) are unaffected and still return `None` without a warning.
* **Built-in data fetching (`df.ta.ticker()`, `ta.yf()`, `ta.av()`)**: emit a `FutureWarning` and will be removed in a future release. Data fetching is out of scope for a technical-analysis library. Fetch OHLCV with `yfinance` / `alpha-vantage` directly and pass the DataFrame to pandas-ta-classic; see the new `examples/fetch_market_data.py` for the replacement patterns. The `data` optional extra remains available during the deprecation window.
* **`ichimoku()` tuple return**: returning a `(visible, span)` tuple is deprecated and now emits a `DeprecationWarning`. The default return becomes a single DataFrame in the next breaking release, and the tuple is removed in the breaking release after that. Pass `as_dataframe=True` to migrate now (add `append_span=True` for the projected span rows). `as_dataframe=False` keeps the tuple and silences the warning for now, but it is deprecated too and will be removed together with the tuple return. The accessor `df.ta.ichimoku()` already returns a DataFrame and is unaffected.
* **`CDL_PATTERN_NAMES`**: Use `ALL_PATTERNS` instead. Accessing the old name emits a `DeprecationWarning`.
* **`tsignals` `drift` parameter**: Passing `drift` now emits a `DeprecationWarning` and the value is ignored — trade signals are always computed with a 1-period difference. The parameter will be removed in a future release.
* **Inactive `drift` parameters on `cfo`, `inertia`, `kst`, `rsx`, `chop`, `accbands`, `kvo`**: These indicators accepted a `drift` parameter that never entered their calculation (dead since the upstream template). Passing `drift` now emits a `DeprecationWarning`; the value has never affected the result and the parameter will be removed in a future release. Indicators that default to the close column (including `series_a`/`series_b` defaults and `df.ta.ichimoku()`) now read the adjusted column, as `docs/dataframe_api.rst` documents. An explicit `close="col"` still wins; `high`, `low`, `open` and `volume` are unaffected; `df.ta.adjusted = None` restores `close`.

* **Native candle patterns went silent on chained input**: `run_pattern` (`candles/_cdl_math.py`) built its running body/shadow averages from the first bar, so a leading NaN run — what every chained indicator produces — made every later average `NaN`, every comparison `False`, and every signal `0`. * **Lookahead-bias test suite** (`tests/test_lookahead.py`): every registered indicator is evaluated over the full series and over two prefixes, and the shared bars must match exactly. The synthetic frame plants flat bars, zero-volume bars, a constant-price run and an extreme bar past the last cut point, since a batch-global branch is only visible when its trigger is in the data (issue #149 was invisible on the SPY sample data, which has no flat bar). Each boolean keyword is additionally flipped one at a time, which is what catches a leak behind a non-default flag such as the old `cdl_z(full=True)`. Each call is its own parametrised case; the ones that look forward on purpose (`dpo` unless `centered=False`, `ichimoku` unless `include_chikou=False`, `tos_stdevall`, `vp`, `cpr(virgin_cpr=True)`) are marked `xfail(strict=True)`, so an exemption cannot go stale in either direction -- an unmarked call that leaks fails, and a marked call that has become causal fails as XPASS.

Calls without `lookahead=False` are unaffected.

The default call is unaffected. `test_lookahead_false_is_all_or_nothing` derives which indicators must honour the keyword (those that already have a causal mode) instead of assuming it, so a future indicator with a switchable forward-looking branch cannot skip it.
* **BREAKING — `mavp` now requires `periods`; the length-dependent default is gone (issue #149 follow-up)**: when `periods` was omitted it defaulted to `linspace(minperiod, maxperiod, len(close))`, so every bar's window length was a function of how many bars were passed in and appending data changed already reported values. `periods` is now a **required** input, as it is in TA-Lib, and has no default at all, so omitting it is a `TypeError` that type checkers catch. `df.ta.mavp()` raises `ValueError`, because the accessor fills missing required arguments with `None` and would otherwise return the source DataFrame unchanged. `mavp` is excluded from `df.ta.strategy()`'s default indicator set for the same reason `tsignals` and `xsignals` are.

The first bar has no standard deviation and stays `NaN`; column names are unchanged.
* **`non_zero_range` leaked future bars into earlier rows (issue #149)**: the epsilon substitution for zero-range bars was applied to *every* row as soon as *any* row in the batch had `high == low`, so appending a single flat bar shifted the whole computed history and batch evaluation disagreed with streaming evaluation. On inputs that contain such a zero, values change by a few ULP for most indicators and by up to 1.5e-6 in `stc` (about 1e-8 relative to its 0–100 scale); they are unchanged otherwise.
* **`df.ta.indicators()` printed nothing** (issue #152): the default (non-`as_list`) call wrote its report via `logger.info()`, and the package installs a `NullHandler`, so users saw no output unless they configured logging themselves. It now prints to stdout again. The return value is unchanged (`None` unless `as_list=True`).
* **Installation-verification snippet in the docs raised `TypeError`** (issue #152): `docs/installation.rst` called `len(df.ta.indicators())`, but the default call returns `None`. Corrected to `len(df.ta.indicators(as_list=True))`.

All 10 category subpackages (`candles`, `cycles`, `math`, `momentum`, `overlap`, `performance`, `statistics`, `trend`, `volatility`, `volume`) now resolve deterministically via the module's `__getattr__` (PEP 562) and are advertised by `dir(pandas_ta_classic)` without requiring prior access. They stay out of `__all__`, which lists the eagerly bound names, so `from pandas_ta_classic import *` is unchanged. Cold-import time is unaffected — the category subpackages still load only on first access, not at `import pandas_ta_classic` time; `volatility` in fact no longer loads eagerly, since the `from . import volatility` that used to force it is redundant now that `__getattr__` resolves every category (the shadowing invariant it guarded is enforced in `utils/__init__.py`, which keeps the `utils.volatility()` metric out of `utils.__all__`). `docs/quickstart.md`'s "List indicators by category" example was also corrected to `ta.Category["momentum"]` etc., since `print(ta.momentum)` only ever printed a module repr, not the indicator list.

* **`tsignals` `drift` corrupted trade signals**: `trends.diff(drift)` computed entries/exits against the state `drift` bars ago instead of the previous bar, so `drift != 1` reported spurious entries mid-trend and missed real crossovers (contradicting the documented `diff()` behavior). Now always uses a 1-period difference. Output at the default (`drift=1`) is unchanged.
* **Cross-package indicator imports**: A submodule import could overwrite a re-exported function of the same name on the parent package (e.g. `from pandas_ta_classic.volatility import atr` occasionally returned the `atr` *module* instead of the function). Resolved.
* **All six `ht_*` indicators crashed on a single NaN**: the Hilbert Transform loop rounds the dominant cycle period with `int(smooth_period + 0.5)` (`cycles/_hilbert.py`), and one NaN anywhere in the input poisons the recursion that feeds it, so `ht_trendline`, `ht_dcperiod`, `ht_dcphase`, `ht_sine`, `ht_phasor` and `ht_trendmode` raised `ValueError: cannot convert float NaN to integer`. A NaN prefix is what every chained indicator produces, so this was reachable from ordinary use. A leading NaN run is now skipped and the transform starts at the first finite close, as TA-Lib does, so chained input produces values instead of an all-`NaN` column (matches `talib.HT_*` to ~1e-11 on shared bars). A NaN later in the series still poisons the recursion; bars from there on emit `NaN` instead of raising — as `tests/test_indicator_edge_cases.py` already required. Output for NaN-free input is unchanged (all 119 TA-Lib oracle tests pass).
* **`candle_color` crashed on a NaN open or close**: it built its result with `close.copy().astype(int)` (`utils/_candles.py`), which raises `IntCastingNaNError` because pandas cannot cast NaN to an integer dtype. This propagated out of `cdl_inside` and `cdl_pattern`. A bar with an undefined colour now yields `NaN` — previously it would have kept whatever the cast produced rather than being classified — and the result is float-typed in that case; fully defined input keeps the historical integer dtype.

When no SMA seed exists the EMA is now all-`NaN`, matching TA-Lib's lookback semantics. Output for inputs that already produced a result is unchanged.

Every sibling indicator (`adx`, `plus_dm`, `minus_dm`) returns `None` there. `dm` now does too. Output for sufficiently long input is unchanged.
* **`cdl_pattern` raised `AttributeError` on short input**: the `doji`/`inside` branch read `pattern_result.name` without checking for `None`, so a sub-pattern that could not be computed (`cdl_doji` needs 10 rows) crashed the whole call with `AttributeError: 'NoneType' object has no attribute 'name'` — via `df.ta.cdl_pattern()` as well. Uncomputable sub-patterns are now skipped, matching the native-pattern branch directly below it; if no pattern can be computed the call returns `None` as documented.
* **Test-fixture regen no longer drops `cmo_14` entries** when running tests without tulipy installed. Generators now merge with existing JSON instead of overwriting.
* **Regression snapshots now cover every tracked indicator** (`tests/test_regression.py`): the file asserted a hand-written list of 43 fixture keys while `regression_snapshots.json` stored 223 — 180 snapshots were generated and never checked, including 55 of the 57 indicators that have no independent oracle and are protected by their snapshot alone. Test methods are generated from the snapshot keys, so the asserted set cannot drift from the stored set again. Out-of-range checkpoints (`vp`, `tos_stdevall` return shorter series) are now asserted to stay out of range instead of raising `IndexError`.

They now share one `golden_value_close()` using `|actual - golden| <= 1e-8 + 1e-6 * |golden|`. The absolute term is the `round(v, 8)` storage floor of the JSON files (the old purely relative check had no floor, so small-magnitude columns were checked 220x looser than the file's own resolution); the relative term covers large-magnitude indicators such as `ad` (~3.8e10), where one float64 ULP is already ~7.6e-6. Measured worst requirement across all 423 tracked columns is 3.6e-15. A 3.3e-7 perturbation of the kurtosis adjustment constant passed under the old tolerance and now fails.
* **Statistics golden values come from exact rational arithmetic** (`tests/fixtures/exact_reference.py`): the oracles for `zscore`, `kurtosis`, `skew`, `median`, `quantile`, `mad`, `entropy`, `beta` and `ui` no longer call `pandas` rolling, whose accumulating power sums drift by up to 1.7e-5 across the SPY series and changed between pandas 2.x and 3.x. Regeneration is now the explicit `make fixtures` step, whose diff must be reviewed. Test-facing only; no runtime behaviour change.
* **`stoch` returned fewer rows than it was given**: `%K` was smoothed from `stoch.loc[stoch.first_valid_index():]` and never reindexed, so the returned DataFrame was `k - 1` rows short (237 rows for 250 of input at the default `k=14`) and carried an index starting `k - 1` bars into the input. The warmup bars are now reported as leading `NaN`, as every sibling indicator does — `stochf` already did. Computed values are unchanged, but a positional read (`.iloc[i]`, `.to_numpy()[i]`) now returns bar `i` instead of bar `i + k - 1`; label-based access is unaffected.
* **`t3` returned ~`length` rows short per EMA stage**: `_ema_chain` (`overlap/ema.py`) trims the leading `NaN` off each stage before seeding the next one — correct — but it also handed the *trimmed* stage back to the caller, contradicting its own docstring ("Each result retains the full index of the original *close*"). `t3` combines stages 3–6 arithmetically, so its output lost 18 rows at the default `length=10` (232 rows for 250 of input). Stages are now reindexed to `close` before being returned, so a positional read of `t3` now returns bar `i` instead of bar `i + 18` at `length=10`. `dema` and `tema` were unaffected in length — pandas realigns their two- and three-stage arithmetic to the union index — and all three keep identical values.
* **`td_seq` replaced the input index with a `RangeIndex`**: the consecutive-run counts were wrapped in a bare `Series(...)` around the numba kernel's numpy output, dropping the caller's DatetimeIndex. Row count was right, so the damage was silent: `df["TD_SEQ_UPa"] = ta.td_seq(df.Close)` aligned an integer index against a datetime one and produced an all-`NaN` column. Values are unchanged.
* **`df.ta.strategy()` shipped unreachable columns to every worker**: the multiprocessing "slim" copy sliced the DataFrame on the *pre-run* column count, so a second run pickled the first run's indicators into every task — 1244 MB over the Pool task pipe instead of 18 MB, a 17 MB single write. On Windows that write fails outright with `OSError: [WinError 1450] Insufficient system resources`; on Linux it only wasted time and memory. The worker copy now carries exactly the columns an indicator can reach: the default OHLCV names, whatever a `close="my_col"`-style kwarg points at (per-indicator dicts of a Custom Strategy included), and `df.ta.adjusted`. A wide caller-supplied DataFrame is trimmed the same way, so payload no longer scales with the frame at all.
* **A failing `df.ta` property reported itself as missing**: an `AttributeError` raised inside a property getter makes Python fall back to `__getattr__`, which answered `'AnalysisIndicators' object has no attribute '<name>'` — a false message, with the real error not even attached as `__context__`. Hit `df.ta.to_utc` and `df.ta.time_range` on a DataFrame without a `DatetimeIndex`, which now report `'RangeIndex' object has no attribute 'tz_localize'` and `'int' object has no attribute 'days'`. Unknown attribute names are unaffected.
* **`df.ta` property setters were silently ignored under pandas 3**: pandas 3 removed accessor caching, so `df.ta` returns a new `AnalysisIndicators` on every access and `df.ta.cores = 0`, `df.ta.adjusted = "adj_close"`, `df.ta.exchange = "LSE"`, and `df.ta.time_range = "months"` were discarded the moment they were assigned. This settable state now lives in `df.attrs` (as `_ta_chain` already did) and survives. `df.ta.last_run` likewise reports the actual last run instead of the accessor's construction time.

## Pre-0.3.78 — Historical

> Items below describe the state of the library as inherited from the original `pandas-ta` project and pre-2026 development. Preserved for historical reference.

### General
* A __Strategy__ Class to help name and group your favorite indicators.
* If a **TA Lib** is already installed, Pandas TA will run TA Lib's version. (**BETA**)
* Some indicators have had their ```mamode``` _kwarg_ updated with more _moving average_ choices with the **Moving Average Utility** function ```ta.ma()```. For simplicity, all _choices_ are single source _moving averages_. This is primarily an internal utility used by indicators that have a ```mamode``` _kwarg_. This includes indicators: _accbands_, _amat_, _aobv_, _atr_, _bbands_, _bias_, _efi_, _hilo_, _kc_, _natr_, _qqe_, _rvi_, and _thermo_; the default ```mamode``` parameters have not changed. However, ```ta.ma()``` can be used by the user as well if needed. For more information: ```help(ta.ma)```
    * **Moving Average Choices**: dema, ema, fwma, hma, linreg, midpoint, pwma, rma, sinwma, sma, swma, t3, tema, trima, vidya, wma, zlma.
* An _experimental_ and independent __Watchlist__ Class located in the [Examples](https://github.com/xgboosted/pandas-ta-classic/tree/main/examples/watchlist.py) Directory that can be used in conjunction with the new __Strategy__ Class.
* _Linear Regression_ (**linear_regression**) is a new utility method for Simple Linear Regression using _Numpy_ or _Scikit Learn_'s implementation.
* Added utility/convience function, ```to_utc```, to convert the DataFrame index to UTC. See: ```help(ta.to_utc)``` **Now** as a Pandas TA DataFrame Property to easily convert the DataFrame index to UTC.

### Breaking / Depreciated Indicators
* _Trend Return_ (**trend_return**) has been removed and replaced with **tsignals**. When given a trend Series like ```close > sma(close, 50)``` it returns the Trend, Trade Entries and Trade Exits of that trend to make it compatible with [**vectorbt**](https://github.com/polakowo/vectorbt) by setting ```asbool=True``` to get boolean Trade Entries and Exits. See ```help(ta.tsignals)```

### New Indicators
* _Arnaud Legoux Moving Average_ (**alma**) uses the curve of the Normal (Gauss) distribution to allow regulating the smoothness and high sensitivity of the indicator. See: ```help(ta.alma)```
* _Draw Down_ (**drawdown**) calculates the percentage decline from the peak equity of a trading account, or fund. See ```help(ta.drawdown)```
* _Candle Patterns_ (**cdl_pattern**) If TA Lib is installed, then all those Candle Patterns are available. See the list and examples above on how to call the patterns. See ```help(ta.cdl_pattern)```
* _Candle Z Score_ (**cdl_z**) normalizes OHLC Candles with a rolling Z Score. See ```help(ta.cdl_z)```
* _Correlation Trend Indicator_ (**cti**) is an oscillator created by John Ehler in 2020. See ```help(ta.cti)```
* _Cross Signals_ (**xsignals**) was introduced in pandas-ta. It is a wrapper of Trade Signals that returns Trends, Trades, Entries and Exits. Cross Signals are commonly used for **bbands**, **rsi**, **zscore** crossing some value either above or below two values at different times. See ```help(ta.xsignals)```
* _Directional Movement_ (**dm**) developed by J. Welles Wilder in 1978 attempts to determine which direction the price of an asset is moving. See ```help(ta.dm)```
* _Even Better Sinewave_ (**ebsw**) measures market cycles and uses a low pass filter to remove noise. See: ```help(ta.ebsw)```
* _Jurik Moving Average_ (**jma**) attempts to eliminate noise to see the "true" underlying activity.. See: ```help(ta.jma)```
* _Klinger Volume Oscillator_ (**kvo**) was developed by Stephen J. Klinger. It is designed to predict price reversals in a market by comparing volume to price.. See ```help(ta.kvo)```
* _Schaff Trend Cycle_ (**stc**) is an evolution of the popular MACD incorportating two cascaded stochastic calculations with additional smoothing. See ```help(ta.stc)```
* _Squeeze Pro_ (**squeeze_pro**) is an extended version of "TTM Squeeze" from John Carter. See ```help(ta.squeeze_pro)```
* _Tom DeMark's Sequential_ (**td_seq**) attempts to identify a price point where an uptrend or a downtrend exhausts itself and reverses. Currently exlcuded from ```df.ta.strategy()``` for performance reasons. See ```help(ta.td_seq)```
* _Think or Swim Standard Deviation All_ (**tos_stdevall**) indicator which
returns the standard deviation of data for the entire plot or for the interval
of the last bars defined by the length parameter. See ```help(ta.tos_stdevall)```
* _Vertical Horizontal Filter_ (**vhf**) was created by Adam White to identify trending and ranging markets.. See ```help(ta.vhf)```
